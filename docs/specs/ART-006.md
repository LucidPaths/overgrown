## Desired result
The pipeline emits every actor animation frame: 9 species × 4 directions × 24 frames = 864 frames of 32×32 in the `core` atlas, named `actor/<species>/<anim>/<dir>/<i>`. Every frame is ART-005's `draw_body` applied to a posed skeleton. A pose is a small per-frame table of joint offsets on top of `base_skeleton`. Right frames are pixel mirrors of left frames. `idle/<dir>/0` is byte-identical to ART-005's base pose. A Python `hand_anchor()` gives ART-009 the main-hand pixel of every frame. A TS table gives TEC-022 each animation's frame count and display timing, and a shared fixture keeps those counts equal to what the pipeline draws. Rebuilds are byte-identical.

### `lib/anims.py`

**The pose model.** A pose moves only the joints listed below. Everything not listed, including every x coordinate of neck, shoulders, hips and tail_root, keeps its `base_skeleton` value.
```python
Offset = tuple[int, int]            # (dx, dy) in screen pixels, y down

@dataclass(frozen=True)
class Pose:
    body: int = 0                   # dy >= 0: hips, neck, shoulders, head and hands sink (crouch, bob)
    chest: int = 0                  # extra dy >= 0: neck, shoulders, head and hands sink (squash, slump)
    head: Offset = (0, 0)           # extra offset on the head joint only
    hand_l: Offset = (0, 0)         # extra offsets on top of body + chest
    hand_r: Offset = (0, 0)
    foot_l: Offset = (0, 0)         # feet ignore body and chest
    foot_r: Offset = (0, 0)
    # __post_init__: ValueError naming the field and value unless:
    #   body in 0..3, chest in 0..4, head dx in -1..1 and dy in 0..3,
    #   hand dx and dy in -10..10, foot dx in -2..2 and dy in -2..0,
    #   at least one foot has dy == 0,
    #   and every number is an int and not a bool, with every Offset a 2-tuple.
```
Why each rule exists. These are the invariants that resolve the ART-005 critic's and Fable gate's coupling findings. Do not relax them.
1. **The head never moves up, and no joint except a hand moves up** (body, chest and head dy ≥ 0). Five species have their ear or crest tips on row 1 (elf, foxfolk, bearfolk, rabbitfolk, birdfolk), so any rise clips.
2. **`tail_root` never moves, in x or y.** The profile torso's depth is mirrored from `tail_root.x` (actor.py `_torso_mask`), so moving it would resize the torso. Lizardfolk and foxfolk tails hang to rows 29–30, so letting the root sink with `body` clips them (prototype: 70+ failures). With the root fixed, a crouching body keeps the tail attached at the lower back.
3. **Shoulders and hips have no per-side offset.** `shoulder_l.y == shoulder_r.y` and `hip_l.y == hip_r.y` hold in every frame by construction, because the torso and clothes read only `shoulder_l.y` and `hip_l.y` (actor.py `_torso_mask`, `_draw_torso_and_clothes`).
4. **There is no whole-body sideways sway.** neck, shoulders, hips and tail_root never move in x. `_toward_centre` (it compares shoulder and hip x against `CENTRE_X`) and the profile torso depth (`2 * neck.x - tail_root.x`) therefore stay valid. Only head, hands and feet move in x.
5. **At least one foot stays on `SOLE_Y`**, so the cell check's lowest-row rule (`SOLE_Y + 1`) holds.
6. **Hands are clamped to `y <= SOLE_Y`** after all offsets, so a hand put "on the ground" works for every arm length. This is the only clamp.

```python

CHEST_SINKS = ("neck", "shoulder_l", "shoulder_r", "head", "hand_l", "hand_r")
```

- **Animated skeletons only ever come from `pose_skeleton`.** That is `apply_pose` on `base_skeleton(species, dir)`, or its mirror. No code builds a `Skeleton` for a frame any other way. So `near` is always the base value for that direction, and `draw_body`'s guard needs no change (this was the ART-005 Fable gate's finding).
- **Why `MAIN_HAND["left"]` is `hand_l`.** In side views the attack swings the near arm, which is `hand_l` when facing left, so the swing is drawn in front of the body. Right frames are mirrors (A-24), and mirroring relabels that arm as `hand_r`. So the anchor is the swinging hand in every direction: `hand_r` in down, up and right, and `hand_l` in left. ART-009 uses `hand_anchor` and never picks the joint itself.
- **Module-level validation, run at import:**
  - `tuple(ANIMS) == ANIM_KEYS`.
  - Every anim has exactly the keys `down`, `left` and `up`, with the same number of poses each.
  - `ANIMS["idle"][d][0] == Pose()` for every d. This is what keeps `idle/<dir>/0` byte-identical to ART-005.

  Each failure raises a `ValueError` naming the anim.
- No species key, `rng`, `random` or `hash(` appears in `lib/anims.py`. Animation is pure data with no randomness.

**How the dodge and the death pose stay inside 32×32.**
- Neither one rotates or translates the body. Both only sink it (body, chest and head dy ≥ 0), so nothing rises above the base pose's top row.
- The feet stay on `SOLE_Y`, and the tail root stays put.
- Hands that drop are clamped to `SOLE_Y`.
- The depth checks in `pose_skeleton` keep at least 2 leg rows and 3 torso rows. The dwarf is the binding case: leg 5 with body 3, torso 7 with chest 4.
- Death therefore ends as a slumped, kneeling heap, not a body lying flat. That is a deliberate M1 limit (see Out of scope).

In the down view, walk frames 1 and 3 come out identical (both are the contact bob). That is expected; no test requires frames to differ.

### `client/src/render/actor-anims.ts` (exactly this content)
```ts
// Actor animation frame counts and display timing (ART-006). Frames: actor/<species>/<anim>/<dir>/<i> (CLAUDE.md).
// `frames` must equal contracts/actor-anims.json; tools/art/tests/test_actor.py checks the pipeline against the same file.
// Timing rule (TEC-022 implements it): e = ticks since the action started (>= 0), i = Math.floor(e / ticksPerFrame);
// a loop shows i % frames, a one-shot shows Math.min(i, frames - 1) and holds its last frame.
export interface ActorAnimTiming {
  readonly frames: number;
  readonly ticksPerFrame: number;
  readonly loop: boolean;
}

export const ACTOR_ANIMS = {
  idle: { frames: 2, ticksPerFrame: 12, loop: true },
  walk: { frames: 4, ticksPerFrame: 3, loop: true },
  attack_blade: { frames: 4, ticksPerFrame: 2, loop: false },
  attack_unarmed: { frames: 4, ticksPerFrame: 2, loop: false },
  dodge: { frames: 4, ticksPerFrame: 2, loop: false },
  hurt: { frames: 2, ticksPerFrame: 3, loop: false },
  death: { frames: 4, ticksPerFrame: 4, loop: false },
} as const satisfies Record<string, ActorAnimTiming>;

export type ActorAnim = keyof typeof ACTOR_ANIMS;
```
Timing at 20 Hz (all values tunable):
- **idle:** 0.6 s per frame, a 1.2 s breath.
- **walk:** 0.15 s per frame, a 0.6 s cycle, which is 48 px at 80 px/s.
- **attack:** 4 × 2 = 8 ticks, exactly CMB-001's `ATTACK_TICKS`.
- **dodge:** shows 0,0,1,1,2,2,3 over `DODGE_TICKS = 7`, so every frame is seen.
- **hurt:** 0.3 s.
- **death:** 0.8 s, then it holds the slumped frame.

The invariant TEC-022 should test once CMB-001 is merged: for a one-shot with a sim duration D, `(frames - 1) * ticksPerFrame < D`. Attack gives 6 < 8 and dodge gives 6 < 7. ART-006 does not import `sim/src/actions.ts`, because CMB-001 may not be merged yet.
