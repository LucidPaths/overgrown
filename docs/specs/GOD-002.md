# GOD-002: Release pipeline (overgrown.exe on GitHub Releases)

Plan: `docs/overhaul/PLAN.md` D2 and § G0 ("**GOD-002** Release pipeline: CI exports Windows and Linux builds and publishes them to GitHub Releases…").
Milestone: G0   Depends on: GOD-001 (merged: `game/`, `tools/godot/setup.sh --templates`, CI `godot` job)
Model: sonnet. The design is locked below.
Branch: god-002-release

## Desired result
Lucid goes to the repo's Releases page and downloads **`overgrown-windows.exe`**: one self-contained file that runs with a double-click. Every push to `main` refreshes a rolling pre-release named **"latest (main)"**. A pushed tag `v*` produces a proper versioned release. A Linux build ships alongside it. Every PR proves the export still works before merge.

## Locked design
1. **`game/export_presets.cfg`** with two presets.
   - **"Windows Desktop":**
     - x86_64;
     - `binary_format/embed_pck=true`, so the whole game is one exe;
     - `application/modify_resources=false`, because rcedit isn't available on Linux runners; we accept the default icon and metadata for now;
     - export path `export/windows/overgrown-windows.exe`.
   - **"Linux":** x86_64, embedded pck, export path `export/linux/overgrown-linux.x86_64`.
   - **Excluded from both:** the tests folder.
2. **Build stamp.**
   - `tools/godot/export.sh` writes `game/build_info.gd` before exporting: `class_name BuildInfo`, with `const COMMIT := "<short sha>"` and `const BUILT_UTC := "<iso time>"`. The file is gitignored.
   - The committed default is generated if missing, so local runs work: `COMMIT := "dev"`.
   - `main.gd`'s label shows `VERSION + " (" + COMMIT + ")"`.
3. **`tools/godot/export.sh`.** It installs templates via `setup.sh --no-blender --templates` if they are missing, writes the build stamp, and runs `godot --headless --path game --export-release "<preset>" <path>` for both presets.
   - It fails with a non-zero exit if either output is missing or empty.
   - It prints the sizes.
4. **PR check:** in `ci.yml`'s `godot` job, after the tests:
   - run `tools/godot/export.sh`;
   - smoke-test the Linux build under `xvfb-run` with `-- --capture /tmp/smoke.png` and require the PNG to exist;
   - upload both binaries with `actions/upload-artifact` (retention 7 days, name `overgrown-builds`).
5. **`.github/workflows/release.yml`:**
   - **Triggers:** `push` to `main`, `push` of tags `v*`, and `workflow_dispatch`.
   - **Permissions:** `contents: write`.
   - **Steps:**
     1. checkout;
     2. cache plus `setup.sh --no-blender --templates`;
     3. `tools/godot/test.sh`;
     4. `tools/godot/export.sh`;
     5. publish with the `gh` CLI, which is preinstalled on runners and uses `GITHUB_TOKEN`.
   - **On `main`:**
     - `gh release delete latest --yes --cleanup-tag || true`;
     - `git push -f origin HEAD:refs/tags/latest`, or let `gh release create` create the tag at the commit;
     - `gh release create latest --prerelease --title "latest (main)" --notes "<commit sha + subject + date + how to run>" --target <sha>` with both binaries.
   - **On a `v*` tag:** `gh release create <tag> --title <tag> --generate-notes` with both binaries.
   - The release notes include a short "How to run" section: download the exe and double-click it. On the first run Windows SmartScreen says "unknown publisher"; click *More info* → *Run anyway*.
6. **Version source.** `GameVersion.VERSION` stays the single version source. A `v*` tag must match it: the release job fails if `tag != "v" + VERSION`.

## Acceptance criteria
- **AC1 Export works locally.** `bash tools/godot/export.sh` → both files exist. `file export/windows/overgrown-windows.exe` → "PE32+ executable … x86-64". `file` on the Linux build → ELF 64-bit. Sizes are reported.
- **AC2 Linux build runs.** The Linux binary run under `xvfb-run` with `-- --capture /tmp/g002.png` → exit 0. View the PNG and report one line confirming the label shows the version and commit.
- **AC3 Workflows are valid.** `python3 -c "import yaml,sys; [yaml.safe_load(open(f)) for f in sys.argv[1:]]" .github/workflows/ci.yml .github/workflows/release.yml` → no error. Read the release job's logic aloud in the report, step by step, for both the main path and the tag path.
- **AC4 Checked by the orchestrator, not you:** after the PR CI is green and the merge to `main`, the "latest (main)" release exists with both files. If the release job fails, the orchestrator fixes it as a follow-up.
- **AC5 Repo tests still pass.** `bash tools/godot/test.sh` → exit 0. `npm run check && npm test` → exit 0, with the venv activated on its own line first.

## Out of scope
- Code signing.
- A custom icon and metadata (needs rcedit or wine; that's a later task).
- macOS builds.
- An auto-updater.
