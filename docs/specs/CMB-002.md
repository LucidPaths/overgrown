## Desired result
On a touch screen, a thumb anywhere in the left half of the screen becomes a floating stick that walks, or sprints at full deflection. A tap on the bottom-right attack circle attacks: toward the nearest other character within 4 tiles and ±30°, else along the stick, else along the facing. A tap on the dodge circle beside it rolls along the stick, else along the facing. All of this travels as the same `InputMessage` that CMB-001 posts, through one shared press counter. Keyboard/mouse and touch both stay live at all times, with no sim change. Nothing is drawn yet; UIX-002 draws it.

## Locked design

### Why a merge layer (read first)
CMB-001's `KeyboardMouseInput` owns its own press counters and posts its own messages. A second adapter that did the same would break the latch: `sim/src/input.ts` reads any counter change as a press. Messages from two adapters with different counters would then fake presses on every alternation, and a keyboard message with `moveX: 0` would cancel a held stick. So both adapters report to one `HostInput`. It owns the only counters and the only posted stream. The sim and the message shape are unchanged.

### Host input merge (`client/src/input/host-input.ts`, new, pure: no DOM)
```ts
export type InputSource = "keyboard-mouse" | "touch";
/** The held (non-edge) part of an InputMessage, as one source sees it. */
export interface HeldInput { moveX: number; moveY: number; aimX: number; aimY: number; sprint: boolean }
export const NO_HELD_INPUT: Readonly<HeldInput>; // all zero / false

export class HostInput {
  /** `initial` is the source assumed active before any input (its held state starts as NO_HELD_INPUT, like every source's). */
  constructor(post: (msg: InputMessage) => void, initial: InputSource);
  /** The source whose held fields are sent: the one with the latest user activity. */
  get active(): InputSource;
  /** `src`'s current held state. `activity`: this came from a user input event, so `src` becomes active.
   *  Posts if the merged message differs from the last posted one. */
  report(src: InputSource, held: HeldInput, activity: boolean): void;
  /** One press: stores `held` for `src`, makes `src` active, counter = (counter + 1) >>> 0, posts.
   *  The press and its held state (e.g. the aim it was made with) are one message. */
  press(src: InputSource, button: "attack" | "dodge", held: HeldInput): void;
}
```
- Merged message = `{ type: "input", ...held[active], attackPresses, dodgePresses }`. Both counters start at 0, matching `createInputLatch`. Dedup compares all 7 fields, like CMB-001's `flush`, which moves here.
- `press` must post exactly one message. Do not call `report` and then post a second time. Messages are separate worker tasks, so a tick can latch between two posts, and the first post would carry a stale aim.
- What counts as activity is locked in each adapter below. Layout updates, blur and visibility changes are never activity.

### Keyboard and mouse adapter (`client/src/input/keyboard-mouse.ts`, changed)
- Constructor becomes `constructor(canvas: HTMLCanvasElement, input: HostInput)`. The private counters, `lastPosted` and `sameInput` are removed. All behaviour in CMB-001's spec is otherwise unchanged: keys, modifiers, `preventDefault` set, pointer filter `mouse`/`pen`, LMB edge on `buttons & 1`, pointer capture, aim, blur/visibility release.
- `flush()` becomes `report("keyboard-mouse", held, activity)` with `held = { moveX, moveY, aimX, aimY, sprint }` computed as today.
- Activity = true for: a bound `keydown` that passes the modifier/repeat filter, every bound `keyup`, and every `pointerdown/move/up/cancel` with `pointerType` `mouse` or `pen` on the canvas. Activity = false for `setLayout` and `releaseAll` (blur, hidden).
- `Space` keydown calls `input.press("keyboard-mouse", "dodge", held)` after adding the code. An LMB 0→1 edge calls `input.press("keyboard-mouse", "attack", held)` after the aim is updated. Each of these replaces that event's `report`.
- The header comment changes from "Touch is CMB-002's" to point at `touch.ts`.

### Touch geometry (`client/src/input/touch-controls.ts`, new, pure: no DOM)
All lengths are CSS px in client coordinates, the same space as `PointerEvent.clientX/Y` and `window.innerWidth/innerHeight`. Every constant is tunable.
```ts
export const STICK_RADIUS_PX = 56;      // knob travel for full deflection
export const STICK_DEAD_ZONE = 0.15;    // fraction of STICK_RADIUS_PX
export const SPRINT_DEFLECTION = 0.9;   // OQ-021 "full stick deflection sprints"
export const EDGE_MARGIN_PX = 16;       // from each safe-area edge
export const ATTACK_RADIUS_PX = 44;     // 88 px button (A-38)
export const DODGE_RADIUS_PX = 28;      // 56 px button (A-38)
export const DODGE_GAP_PX = 12;         // horizontal gap between attack and dodge
export const RING_SLOT_RADIUS_PX = 24;  // 48 px slots
export const RING_DISTANCE_PX = 128;    // slot centre to attack centre
export const RING_ANGLES_DEG = [75, 105, 135, 165] as const; // 0 = right, 90 = up on screen

export interface Insets { top: number; right: number; bottom: number; left: number }
export interface Circle { x: number; y: number; r: number } // centre + radius
export interface TouchLayout {
  viewW: number;
  viewH: number;
  /** Where UIX-002 draws the idle floating stick. Visual only, not a hit area. r = STICK_RADIUS_PX. */
  stickRest: Circle;
  attack: Circle;
  dodge: Circle;
  /** Ability ring, in RING_ANGLES_DEG order. Disabled until CMB-003. */
  ring: readonly [Circle, Circle, Circle, Circle];
}
export type TouchTarget = "attack" | "dodge" | "ring" | "stick" | null;

export function layoutTouchControls(viewW: number, viewH: number, insets: Insets): TouchLayout;
export function hitTest(layout: TouchLayout, x: number, y: number): TouchTarget;
export function stickToMove(dx: number, dy: number): { moveX: number; moveY: number; sprint: boolean };
```
- **Layout** (`L, R, T, B` = insets):
  - attack centre `A = (viewW − R − EDGE_MARGIN_PX − ATTACK_RADIUS_PX, viewH − B − EDGE_MARGIN_PX − ATTACK_RADIUS_PX)`;
  - dodge centre `(A.x − ATTACK_RADIUS_PX − DODGE_GAP_PX − DODGE_RADIUS_PX, A.y + ATTACK_RADIUS_PX − DODGE_RADIUS_PX)`, i.e. left of attack with the bottoms aligned (OQ-026 "dodge beside it");
  - ring slot k centre `(A.x + RING_DISTANCE_PX·cos θk, A.y − RING_DISTANCE_PX·sin θk)`, with θk in radians from `RING_ANGLES_DEG`. These are client-side floats; trig is allowed here because the code is not seeded;
  - stickRest `(L + EDGE_MARGIN_PX + STICK_RADIUS_PX, viewH − B − EDGE_MARGIN_PX − STICK_RADIUS_PX)`.
  - At 412×915 with zero insets: attack (352, 855), dodge (268, 871), ring ≈ (385.13, 731.36), (318.87, 731.36), (261.49, 764.49), (228.36, 821.87), stickRest (72, 843). The scripted checks tap these points.
  - Supported down to 360 CSS px wide (portrait) and 320 tall (landscape). Below 336 px wide, the stickRest circle touches the 165° ring slot. That overlap is visual only and recorded as a limitation.
- **Hit test.** Circles are inclusive: `(x−cx)² + (y−cy)² ≤ r²`. Priority order: attack, dodge, ring slots, then `"stick"` if `x < viewW / 2` (the whole left half, insets included), else `null`. Buttons beat the stick zone, which matters where a ring slot crosses the midline on narrow phones.
- **Stick mapping.** `d = Math.sqrt(dx*dx + dy*dy)` and `m = d / STICK_RADIUS_PX`.
  - If `m ≤ STICK_DEAD_ZONE`: `{0, 0, false}`.
  - Else, with `(ux, uy) = (dx / d, dy / d)`:
    - if `m ≥ SPRINT_DEFLECTION`: `mag = 1`, `sprint = true`;
    - else `mag = (m − STICK_DEAD_ZONE) / (1 − STICK_DEAD_ZONE)`, `sprint = false`.
  - `moveX = clamp(ux·mag, −1, 1)`, and the same for y. The clamp guarantees the sim's [-1, 1] bound against float rounding: an out-of-range axis is a RangeError that kills the sim.
  - At full deflection the move is unit length, so sprint is exactly ×1.6 walk (OQ-021).
  - RangeError naming the value if `dx` or `dy` is not finite.

### Soft auto-aim (`client/src/input/auto-aim.ts`, new, pure: no DOM)
```ts
export const AUTO_AIM_RANGE_PX = 4 * TILE_PX;  // 64 world px, OQ-026, tunable
export const AUTO_AIM_HALF_ANGLE_DEG = 30;     // OQ-026, tunable
/** World-px offset from `frame.you`'s feet to the nearest other living Character within AUTO_AIM_RANGE_PX
 *  whose bearing is within ±AUTO_AIM_HALF_ANGLE_DEG of (dirX, dirY); null if there is none, if the direction is (0, 0),
 *  or if `you` is not in the frame. */
export function pickAutoAim(frame: Frame, dirX: number, dirY: number): { x: number; y: number } | null;
```
- Candidates: `i < frame.count` with `kind[i] === Kind.Character`, `ids[i] !== frame.you` and `action[i] !== Action.Death`. Offset `(ox, oy) = (x[i] − youX, y[i] − youY)`, distance `dist = Math.sqrt(ox² + oy²)`. Skip `dist === 0`, since it has no bearing.
- In range: `dist ≤ AUTO_AIM_RANGE_PX`. In the cone: `(ox·dirX + oy·dirY) / |dir| ≥ cos(30°)·dist`, so the edges are inclusive and `dir` need not be unit length.
- Nearest wins. On an exact distance tie, the smaller EntityId wins, so the result never depends on snapshot order.
- Not filtered by hostility; factions are later tasks. M1 has one character, so the picker returns null, but it must be correct.
- Facing → unit vector (used by `touch.ts` for the no-stick cone axis): import `FACING_UNIT` from `@overgrown/sim/actions`. The one sim change in this task is adding `export` to that existing constant, so there is still one copy of the rule.

### Touch adapter (`client/src/input/touch.ts`, new)
```ts
export interface StickView { originX: number; originY: number; knobX: number; knobY: number } // CSS client px
export interface ButtonsDown { attack: boolean; dodge: boolean }
/** Layout for the current viewport: window.innerWidth/innerHeight and the env(safe-area-inset-*) values. */
export function currentTouchLayout(): TouchLayout;
export class TouchInput {
  /** `frame` is main's reused Frame (updated in place every render frame); read only at press time. */
  constructor(canvas: HTMLCanvasElement, input: HostInput, frame: Frame);
  /** The active stick, knob clamped to STICK_RADIUS_PX from the origin; null when no stick is held. For UIX-002. */
  get stick(): StickView | null;
  /** True while at least one touch that went down on that button is still down. For UIX-002 (and CMB-013 later). */
  get buttonsDown(): ButtonsDown;
}
```
- **Safe-area insets.** A private probe element is created on first use and appended to `document.body`: `position: fixed; left: 0; top: 0; width: 0; height: 0; visibility: hidden; pointer-events: none; padding: env(safe-area-inset-top, 0px) env(safe-area-inset-right, 0px) env(safe-area-inset-bottom, 0px) env(safe-area-inset-left, 0px)`. Insets = `parseFloat` of its computed padding. `client/index.html` already has `viewport-fit=cover`. `currentTouchLayout()` is called on every touch `pointerdown`, so rotation needs no listener.
- **Listeners** on the canvas: `pointerdown`, `pointermove`, `pointerup`, `pointercancel`, handling only `pointerType === "touch"`. No `preventDefault` (`touch-action: none` already blocks scroll and zoom). On `window` `blur`, and on `document` `visibilitychange` to hidden: release the stick, clear `buttonsDown`, `report(…, false)`.
- **State:** `stickId: number | null`, origin and current point; `downOn: Map<pointerId, "attack" | "dodge">`; `aim` (the touch source's carried aim, initially (0, 0)).
- **Held state** = `{ ...stickToMove(cur − origin) (or zeros without a stick), aimX, aimY }`. "Stick active" below means the stick's move is non-zero (outside the dead zone).
- **pointerdown** → `hitTest(currentTouchLayout(), clientX, clientY)`:
  - `"attack"`: `downOn.set(id, "attack")`. Aim:
    - if the stick is active, `dir` = the stick move; else, if `you` is in the frame, `dir` = `FACING_UNIT[facing of you]`; else no dir.
    - `target = dir ? pickAutoAim(frame, dir.x, dir.y) : null`.
    - `aim = target ?? (stick active ? normalize(stick move) × AUTO_AIM_RANGE_PX : (0, 0))`.
    - The sim only reads the aim's direction (OQ-025: facing snaps to it). (0, 0) keeps the current facing.
    - Then `input.press("touch", "attack", held)`.
  - `"dodge"`: `downOn.set(id, "dodge")`, `aim = (0, 0)`, then `input.press("touch", "dodge", held)`. With aim zero, CMB-001's rule rolls along the move (the stick) if any, else along the facing, and the facing is kept.
  - `"stick"`: if `stickId === null`, start the stick there (origin = current = the point, move 0) and call `canvas.setPointerCapture(id)`. A second finger in the zone is ignored. Then `report("touch", held, true)`.
  - `"ring"` or `null`: `report("touch", held, true)` only. Ring slots do nothing until CMB-003, and an empty right half is reserved for tap-to-target, which has no task in M1.
- **pointermove** of `stickId`: update the current point, `report("touch", held, true)`. Other pointers: nothing.
- **pointerup / pointercancel**: `downOn.delete(id)`. If it is `stickId`: release (move 0, sprint false). Then `report("touch", held, true)`.
- The carried aim is kept until the next attack or dodge press. The sim reads aim only when an action starts, and every dodge press zeroes it in its own message, so a stale target aim cannot steer a later roll.

### Wiring (`client/src/main.ts`)
Replace the `KeyboardMouseInput` construction (after `init` is posted) with:
```ts
const hostInput = new HostInput(
  (msg) => worker.postMessage(msg),
  window.matchMedia("(pointer: coarse)").matches ? "touch" : "keyboard-mouse",
);
const input = new KeyboardMouseInput(app.canvas, hostInput);
const touch = new TouchInput(app.canvas, hostInput, frame);
```
The ticker keeps calling `input.setLayout(layout)`. `touch` has no per-frame call in this task; UIX-002 reads it. `initial` changes nothing in the messages, because every held state starts at zero. It is the device UIX-002 shows before any input (A-39).

const URL = "http://localhost:4202/?seed=1";

const near = (a, b, tol) => Math.abs(a - b) <= tol;
