# WLD-001: Chunk generator (seed + chunk coordinates → tile layer)

GDD: docs/gdd/02-world.md — "**WLD-001** `[proto]` Chunk generator: seed + coordinates → tile layer (deterministic, tested)."
Milestone: M1   Depends on: none
Model: opus — because this creates the Tile enum, the chunk constants and the worldgen noise that WLD-002/003/004 and ART-004 all build on, and a cross-engine float divergence would silently give peers different worlds.
Branch: wld-001-chunk-gen

## Desired result
`generateChunk(seed, cx, cy)` in the sim returns a 32×32 `Uint8Array` of `Tile` values that is a pure, bit-exact function of its inputs and seamless across chunk borders. The values come from one elevation field built on a new deterministic noise module. Pinned digests prove determinism, tests prove the seams, and a lint rule stops engine-dependent `Math` functions from entering worldgen.

## Locked design

### Coordinates and constants (M1 contract, verbatim)
- y-down. World pixel (0,0) is the top-left of tile (0,0), and tile (0,0) is the top-left tile of chunk (0,0).
- `tile = Math.floor(px / TILE_PX)`, `chunk = Math.floor(tile / CHUNK_TILES)`. Floor division everywhere, so negative coordinates need no special case.
- Local tile index inside a chunk: `ly * CHUNK_TILES + lx`. World tile of a local tile: `tx = cx * CHUNK_TILES + lx`, `ty = cy * CHUNK_TILES + ly`.
- `sim/src/constants.ts` gains, below the existing lines:
  ```ts
  /** Ground tile edge in world pixels. */
  export const TILE_PX = 16;
  /** Chunk edge in tiles; a chunk holds CHUNK_TILES * CHUNK_TILES tiles. */
  export const CHUNK_TILES = 32;
  ```
  `TILE_PX` has no consumer in this task. It is a contract constant for WLD-003/004, not dead code.

### `sim/src/rng.ts` refactor (no output change)
The noise lattice is defined as `deriveSeed(octaveSeed, ix, iy)`, which keeps it reproducible from the shared RNG contract (Python's `derive_seed` gives the same values). Calling `deriveSeed` per lattice corner costs about 1 ms per chunk in Node, because of argument validation and the `forEach` closure. Measured with a scratch reference implementation: about 0.22 ms per chunk with the unchecked step below, against about 1.05 ms with `deriveSeed`. WLD-002 will add more fields and WLD-003 generates about 25 chunks at startup inside a 0.2–0.35 s first-frame margin, so the fast path is locked.
- `fmix32` becomes `export function fmix32(x: number): number` (body unchanged).
- New export, placed right after `fmix32`:
  ```ts
  /** One deriveSeed combine step, UNCHECKED (hot paths only): part must be an integer in -2^31..2^32-1. */
  export function mixSeedPart(h: number, part: number): number {
    return (fmix32(h ^ fmix32(part >>> 0)) + GOLDEN) >>> 0;
  }
  ```
- `deriveSeed` keeps its validation and loop, but its combine line becomes `h = mixSeedPart(h, p);` instead of repeating the formula. One formula, one place.
- `contracts/rng-vectors.json`, `rng.test.ts` and `tools/art/lib/rng.py` do not change. The existing vectors prove the refactor changed nothing.

### `sim/src/world/noise.ts` (new)
Public API: exactly these two exports.
```ts
/** A continuous 2-D scalar field over world tile coordinates, values in [0, 1). */
export type Field2 = (x: number, y: number) => number;

/**
 * Fractal value noise: one octave per wavelength (in tiles), amplitude halving each octave, normalised to [0, 1).
 * Bit-identical in every JS engine: only + - * /, Math.floor and 32-bit integer ops.
 * Domain: finite x, y in [-2^31, 2^31). Not checked per call (hot path); callers that take outside input validate it
 * (generateChunk does).
 */
export function createFbm(seed: number, wavelengths: readonly number[]): Field2;
```
The algorithm is locked, including the order of operations, because the golden values below depend on it:
```
createFbm(seed, wavelengths):
  validate: wavelengths.length >= 1, and every w is an integer >= 1,
            else throw RangeError naming the index and the value ("wavelengths[2] must be an integer >= 1, got 0")
            (seed is validated by deriveSeed below, which throws its own RangeError)
  for i = 0 .. n-1:                          # computed once, here, not per sample
    h[i]   = fmix32(deriveSeed(seed, i))     # lattice state for octave i
    amp[i] = 1 for i = 0, else amp[i-1] * 0.5
  norm = amp[0] + amp[1] + ... (summed in index order)
  return (x, y) => {
    total = 0
    for i = 0 .. n-1: total += amp[i] * octave(h[i], wavelengths[i], x, y)
    return total / norm
  }

octave(h, w, x, y):
  gx = x / w;  gy = y / w
  ix = Math.floor(gx);  iy = Math.floor(gy)
  fx = fade(gx - ix);   fy = fade(gy - iy)          fade(t) = t * t * (3 - 2 * t)
  v(i, j) = mixSeedPart(mixSeedPart(h, i), j) / 4294967296     # === deriveSeed(octaveSeed, i, j) / 2^32
  top    = lerp(v(ix, iy),     v(ix + 1, iy),     fx)          lerp(a, b, t) = a + (b - a) * t
  bottom = lerp(v(ix, iy + 1), v(ix + 1, iy + 1), fx)
  return lerp(top, bottom, fy)
```
Properties the tests rely on:
- At integer lattice points (fx = fy = 0), a one-octave field equals `deriveSeed(deriveSeed(seed, 0), ix, iy) / 2^32` exactly.
- Adjacent integer samples differ by at most `1.5 · Σ(amp[i] / w[i]) / Σ amp[i]`, where 1.5 is the maximum slope of `fade`.

### `sim/src/world/chunk-gen.ts` (new)
```ts
export interface ChunkData { cx: number; cy: number; tiles: Uint8Array<ArrayBuffer> }   // tiles.length === CHUNK_TILES * CHUNK_TILES

/** Elevation octaves in tiles (tunable). Exported for the seam test's slope bound. */
export const ELEVATION_WAVELENGTHS = [128, 64, 32, 16] as const;

/** The elevation field for a world seed: createFbm(deriveSeed(seed, hashString("elevation")), ELEVATION_WAVELENGTHS). */
export function createElevation(seed: number): Field2;

/** PLACEHOLDER classification (WLD-002 replaces it with the biome map). Bands are upper-exclusive, checked in order. */
export function classifyElevation(e: number): TileValue;
//   e < 0.25 → VeryDeepWater
//   e < 0.32 → DeepWater
//   e < 0.38 → ShallowWater
//   e < 0.42 → Sand
//   e < 0.68 → Grass
//   else     → Stone
// (all thresholds tunable; keep them as one named constant table)

export function generateChunk(seed: number, cx: number, cy: number): ChunkData;
//   validate seed: integer in 0..4294967295, else RangeError ("seed must be an integer in 0..4294967295, got …")
//   validate cx, cy: integers in -2^26..2^26-1 (so world tile coords fit in int32, the noise domain),
//                    else RangeError naming the argument and value ("cx must be an integer in -67108864..67108863, got 0.5")
//   elev = createElevation(seed)
//   for ly in 0..31, lx in 0..31: tiles[ly * CHUNK_TILES + lx] = classifyElevation(elev(cx * CHUNK_TILES + lx, cy * CHUNK_TILES + ly))
//   return { cx, cy, tiles }
```
Noise is always sampled at **world** tile coordinates. That makes chunk borders seamless by construction and lets WLD-002/005 keep rivers and coasts continuous.

For context only (not an AC): the reference implementation produced this mix over chunks [-8,8)² for seed 42: Grass 52.9 %, ShallowWater 15.5 %, Stone 11.3 %, Sand 9.9 %, DeepWater 8.7 %, VeryDeepWater 1.7 %.

### Determinism guard: `eslint.config.js`
Add one block, after the existing ones. Every file under `sim/src/world/` (WLD-002/004 inherit it) may use only the `Math` members the M1 contract allows, no `**`, and no `Date`:
```js
{
  files: ["sim/src/world/**/*.ts"],
  rules: {
    "no-restricted-syntax": [
      "error",
      {
        selector: "MemberExpression[object.name='Math'][property.name!=/^(imul|floor|abs|min|max)$/]",
        message: "Worldgen must be bit-identical in every JS engine: only Math.imul/floor/abs/min/max, + - * / and bit ops (CLAUDE.md contracts).",
      },
      {
        selector: "BinaryExpression[operator='**'], AssignmentExpression[operator='**=']",
        message: "Worldgen must be bit-identical in every JS engine: no ** (pow is not exactly rounded).",
      },
      { selector: "Identifier[name='Date']", message: "No wall-clock time in seeded code." },
    ],
  },
},
```
Why this is not ceremonial: vitest only runs on V8, so a `Math.sin`, `Math.pow` or `**` in noise passes every test here and then silently gives Firefox/Safari peers different chunks. Lint is the only guard that can see it. The selectors were checked against ESLint 10 + typescript-eslint in this repo: they flag `Math.sin/random/sqrt/["cos"]`, `**`, `**=`, `Date.now()` and `new Date()`, and pass `Math.imul/floor/abs/min/max`.

## Tests
Compute the digest of a chunk inside the test as `deriveSeed(0, ...chunk.tiles)`. It reuses the RNG contract and needs no new hash code.

`sim/src/world/chunk-gen.test.ts`
1. **Golden digests** (`it.each`). Assert `chunk.cx`/`chunk.cy` echo the inputs, `tiles.length === 1024`, and the digest. This guards against any silent change to worldgen output: same seed, different world after an update, a save or a peer mismatch. Cases cover every placeholder tile, negative coordinates, both seed extremes and both ends of the coordinate range:

   | seed | cx | cy | digest | tiles present (for orientation) |
   |---|---|---|---|---|
   | 42 | 0 | 0 | 3156299026 | Grass, Sand, ShallowWater, DeepWater |
   | 42 | -5 | -5 | 1621497478 | Sand, ShallowWater, DeepWater, VeryDeepWater |
   | 42 | -1 | -8 | 1005403038 | Grass, Stone |
   | 0 | -2 | -6 | 2625681554 | Grass, Sand, ShallowWater, DeepWater |
   | 4294967295 | -5 | 0 | 2736794256 | Grass, Sand, ShallowWater, DeepWater, VeryDeepWater |
   | 4294967295 | 7 | -7 | 3476723864 | Grass, Stone |
   | 42 | -67108864 | 67108863 | 1958065395 | Grass, Sand |
2. **Seam: chunk = field at world coords.** For seed 42 and chunks (-1,-1), (0,-1), (-1,0), (0,0) and (3,-7), every tile `tiles[ly*32+lx]` equals `classifyElevation(createElevation(42)(cx*32+lx, cy*32+ly))`. Guards against sampling noise with local instead of world coordinates. To show it can fail, temporarily pass `lx, ly` to `elev` in `generateChunk`.
3. **Seam: the field has no jumps.** For `createElevation(42)`, every horizontally and vertically adjacent pair with `tx, ty` in [-64, 64) (which crosses the chunk borders at -32, 0 and 32 on both axes) differs by at most `1.5 * Σ(0.5^i / W[i]) / Σ 0.5^i + 1e-12`, with `W = ELEVATION_WAVELENGTHS`. That bound is 0.025 for the starting values; the reference measured a maximum of 0.0098. Together with test 2 this proves seamlessness: test 2 ties chunks to the field, and this test rules out a field that re-seeds per chunk or per cell. To show it can fail, temporarily replace `fade(t)` with `0` (nearest-lattice values).
4. **Validation.** `generateChunk(42, 0.5, 0)`, `generateChunk(42, 2 ** 26, 0)`, `generateChunk(42, 0, -(2 ** 26) - 1)`, `generateChunk(-1, 0, 0)` and `generateChunk(2 ** 32, 0, 0)` each throw a RangeError whose message names the argument. Guards against a fractional chunk coordinate, for example a WLD-003 caller forgetting `Math.floor`, silently producing a shifted chunk.

`sim/src/world/noise.test.ts`
5. **Golden values.** `createFbm(7, [64, 16])` at these points, compared with `toBe` (exact):

   | (x, y) | value |
   |---|---|
   | (0, 0) | 0.27640928483257693 |
   | (37, -5) | 0.47350522662102396 |
   | (-1000, 2049) | 0.6012487562564303 |
   | (-2147483648, 2147483647) | 0.6524181601223612 |
   | (0.5, -0.25) | 0.2761308198732707 |

   Guards the noise itself independently of classification. WLD-002 will re-pin the chunk digests when it replaces the classification, and these values still catch noise drift.
6. **Lattice is `deriveSeed`.** `createFbm(1, [1])(3, 4) === deriveSeed(deriveSeed(1, 0), 3, 4) / 2 ** 32` (= 0.8629811755381525). Guards the cross-language definition: the Python pipeline can reproduce worldgen noise with `derive_seed` alone. Tests 5 and 6 can each be shown to fail by changing `GOLDEN` in `mixSeedPart` (the rng vectors fail too). Revert afterwards.
7. **Validation.** `createFbm(1, [])`, `createFbm(1, [0])` and `createFbm(1, [1.5])` throw a RangeError naming the wavelength index or the empty list. Guards against w = 0 or NaN, which turn the lattice index into NaN; `NaN >>> 0` is 0, so the result would be a silently constant field.

Not tested (deliberately): performance (WLD-003 owns the streaming budget; the reference measured ~0.2–0.6 ms/chunk in Node); tile-mix proportions (placeholder, replaced by WLD-002); the forbidden-ops rule (it is lint, proven by AC7, not a vitest test).
