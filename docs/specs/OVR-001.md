# OVR-001 (+ TEC-019): Repo scaffold with a browser-free sim package

GDD: docs/gdd/00-overview.md — "Repo scaffold: TS client, Python asset pipeline, CI that builds both and fails on lint or type errors."
Also implements docs/gdd/01-tech.md — "TEC-019 CI guard: the sim package builds with no DOM/browser types available, so browser API use in the sim fails the build." (Folded in because the guard *is* the sim tsconfig this task creates; splitting it would create a no-op PR.)
Milestone: M0   Depends on: none
Model: opus — because every later task inherits this layout, tooling and CI; mistakes here multiply.
Branch: ovr-001-scaffold

## Desired result
A clean clone can run `npm ci && npm run check && npm test && npm run build`, and so can CI on every push and PR. The repo has two npm workspaces, `sim` (pure TS, *cannot* see browser APIs) and `client` (Vite app that imports from `sim`), plus a Python tooling area at `tools/art`. Lint or type errors anywhere fail CI.

## Locked design

Layout (create exactly this; no other top-level dirs):
```
package.json            private, "type": "module", workspaces ["sim", "client"], engines node >=22
package-lock.json       committed
tsconfig.base.json      shared compiler options (below)
eslint.config.js        flat config: @eslint/js recommended + typescript-eslint recommended (NOT type-checked rules); ignore dist/, node_modules/, client/public/generated/
.nvmrc                  22
.gitignore              add: node_modules/, dist/, client/public/generated/, __pycache__/, .pytest_cache/, .ruff_cache/, *.tsbuildinfo  (keep the existing .scratch/ line)
sim/package.json        name "@overgrown/sim", private, type module, "exports": { "./*": "./src/*.ts" }, scripts: typecheck = tsc --noEmit -p .
sim/tsconfig.json       extends ../tsconfig.base.json; compilerOptions.lib ["ES2022"], types []; include ["src"]
sim/src/version.ts      export const SIM_VERSION = "0.0.0";
client/package.json     name "@overgrown/client", private, type module, deps: "@overgrown/sim": "*" (workspace); devDeps: vite; scripts: dev, build (vite build), preview, typecheck (tsc --noEmit -p .)
client/tsconfig.json    extends base; lib ["ES2022", "DOM", "DOM.Iterable"]; types ["vite/client"]; include ["src"]
client/vite.config.ts   base: "./" (the site will be served from a subpath on GitHub Pages)
client/index.html       mobile viewport meta (width=device-width, initial-scale=1, viewport-fit=cover), <div id="app">, loads /src/main.ts
client/src/main.ts      imports SIM_VERSION from "@overgrown/sim/version" and writes "overgrown — sim v<version>" into #app (proves the workspace link; TEC-001 replaces it with Pixi)
tools/art/requirements.txt       pillow, numpy (pinned ==, to the versions you install)
tools/art/requirements-dev.txt   -r requirements.txt, ruff, pytest (pinned)
tools/art/pyproject.toml         ONLY tool config: [tool.ruff] target-version "py313", line-length 100; [tool.pytest.ini_options] pythonpath ["."], testpaths ["tests"]
tools/art/build.py               entry point; for now logs "overgrown art pipeline: no generators registered yet" and exits 0 (ART-001 fills it in)
.github/workflows/ci.yml         see below
```

tsconfig.base.json compilerOptions: target ES2022, module ESNext, moduleResolution Bundler, strict true, noUncheckedIndexedAccess true, noImplicitOverride true, verbatimModuleSyntax true, isolatedModules true, skipLibCheck true, noEmit true.

Root package.json scripts (exact names, other tasks rely on them):
- `check`: typecheck both workspaces + eslint + ruff check + ruff format --check (Python commands run from tools/art). Python tools are invoked as `python3 -m ruff` / `python3 -m pytest` so whatever env is active is used.
- `test`: `vitest run --passWithNoTests` at the root (vitest as root devDependency; a root vitest.config.ts is allowed only if needed), then pytest in tools/art, treating pytest exit code 5 (no tests collected) as success.
- `build`: `python3 tools/art/build.py && npm -w @overgrown/client run build`
- `dev`: `npm -w @overgrown/client run dev`

ci.yml: on push to main and on pull_request. One job, ubuntu-latest: checkout; setup-node 22 with npm cache; setup-python 3.13; `pip install -r tools/art/requirements-dev.txt`; `npm ci`; `npm run check`; `npm test`; `npm run build`.

Dependencies: use the current stable major of each (typescript, vite, vitest, eslint, @eslint/js, typescript-eslint). No other npm dependencies.

No barrel files: no `index.ts` re-exporting modules. Consumers import modules by path (`@overgrown/sim/version`). This keeps parallel tasks from editing the same file.

Delegated micro-decisions: exact pinned versions; script implementation details (shell one-liners vs `npm-run-all`, but no extra deps for that: plain `&&` is fine); eslint rule tweaks needed to pass on this code.

## Acceptance criteria
- AC1 Fresh install and full pipeline green — proven by: `rm -rf node_modules && npm ci && npm run check && npm test && npm run build` → all exit 0.
- AC2 Sim cannot see browser APIs (TEC-019) — proven by: temporarily adding `export const x = document.title;` to `sim/src/version.ts` makes `npm run check` fail with a "Cannot find name 'document'" error; revert afterwards. Same for `window` and `self`.
- AC3 Client can see browser APIs and the sim — proven by: `npm run build` succeeds and `client/dist/index.html` exists; `grep -r "sim v" client/dist/assets/*.js` finds the string.
- AC4 Lint actually runs — proven by: temporarily adding `const unused = 1;` to client/src/main.ts makes `npm run check` fail; an unformatted Python line in tools/art/build.py makes it fail too; revert both.
- AC5 build.py runs — proven by: `python3 tools/art/build.py` → exit 0 with the log line.
