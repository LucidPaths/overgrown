# CHR-001: Character entity shared by players and NPCs

GDD: docs/gdd/04-characters.md — "**CHR-001** `[proto]` Character entity shared by players and NPCs (same component set)."
Milestone: M1   Depends on: none (M0 merged). Runs in parallel with WLD-001 and ART-005; this task does not touch their files (`sim/src/constants.ts`, `sim/src/world/**`, `tools/art/gen/__init__.py`, new generators, palettes).

Branch: chr-001-character-entity

## Desired result
The sim has one character entity, built by one `spawnCharacter` path for players and NPCs alike, and one movement system that turns any character's Intent into motion, facing and an Idle/Walk action. On start the sim spawns the local player (Human) at world (0,0), and every snapshot carries facing, action, action start tick, species and `you`. The debug movers are gone. The page shows one static placeholder character at the centre of the canvas.

## Locked design

### Protocol (`sim/src/protocol.ts`): the M1 contract, verbatim
```ts
export const Kind = { Character: 1 } as const;                 // replaces DebugMover; 0 stays "unset"
export const Facing = { Down: 0, Left: 1, Right: 2, Up: 3 } as const;
export const Action = { Idle: 0, Walk: 1, Attack: 2, Dodge: 3, Hurt: 4, Death: 5 } as const;
export const Species = {
  Human: 0, Elf: 1, Dwarf: 2, Orc: 3, Foxfolk: 4, Bearfolk: 5, Rabbitfolk: 6, Birdfolk: 7, Lizardfolk: 8,
} as const;
export type KindValue = (typeof Kind)[keyof typeof Kind];       // moved here from kind-frames.ts
export type FacingValue = (typeof Facing)[keyof typeof Facing];
export type ActionValue = (typeof Action)[keyof typeof Action];
export type SpeciesValue = (typeof Species)[keyof typeof Species];

export interface Snapshot {
  tick: number;
  count: number;
  ids: Uint32Array<ArrayBuffer>;
  x: Float32Array<ArrayBuffer>;            // absolute world px, y-down; the character's feet point
  y: Float32Array<ArrayBuffer>;
  kind: Uint16Array<ArrayBuffer>;
  facing: Uint8Array<ArrayBuffer>;         // FacingValue
  action: Uint8Array<ArrayBuffer>;         // ActionValue
  actionStart: Uint32Array<ArrayBuffer>;   // tick of the first snapshot that shows this action
  species: Uint8Array<ArrayBuffer>;        // SpeciesValue
  /** The local player's EntityId, or -1 if none (EntityIds are never negative). */
  you: number;
}
export function snapshotBuffers(s: Snapshot): ArrayBuffer[]   // all 9 column buffers
```
`HostToSim` and `SimToHost` are unchanged. The species frame-name keys (`human`, …) are not added here. TEC-022 adds them when it consumes them.

### Character module (`sim/src/character.ts`, new)
```ts
export const FOOT_HALF_W = 5; // px; 10×6 foot box (OQ-025), tunable
export const FOOT_HALF_H = 3;

export interface CharacterComponents {
  position: Component<{ x: "f64"; y: "f64" }>;        // feet point = the sprite's bottom centre
  velocity: Component<{ vx: "f64"; vy: "f64" }>;      // px/s, written by movement
  facing:   Component<{ dir: "u8" }>;                 // FacingValue
  collider: Component<{ hw: "f32"; hh: "f32" }>;      // half-extents; box = [x-hw, x+hw] × [y-2hh, y]
  intent:   Component<{ moveX: "f32"; moveY: "f32"; aimX: "f32"; aimY: "f32"; buttons: "u8" }>;
  action:   Component<{ state: "u8"; start: "u32" }>; // ActionValue + start tick
  species:  Component<{ species: "u8" }>;             // SpeciesValue
  kind:     Component<{ kind: "u16" }>;               // KindValue
}
/** The ECS world plus the character components registered in it. */
export interface CharacterWorld { readonly ecs: World; readonly components: CharacterComponents }

export function createCharacterWorld(ecs: World): CharacterWorld;   // registers the 8 components above
export interface SpawnCharacterOptions { x: number; y: number; species: SpeciesValue; tick: number }
export function spawnCharacter(world: CharacterWorld, opts: SpawnCharacterOptions): EntityId;
```
- The component names passed to `register` are `"Position"`, `"Velocity"`, `"Facing"`, `"Collider"`, `"Intent"`, `"Action"`, `"Species"` and `"Kind"`.
- `spawnCharacter` is the only way to make a character, whether player or NPC. It adds all 8 components and sets Position = (x, y), Velocity 0, Facing Down, Collider (FOOT_HALF_W, FOOT_HALF_H), Intent all zero, Action Idle with start = `opts.tick`, Species = `opts.species` and Kind Character. It throws a `RangeError` naming the value if `x` or `y` is not finite. No HP, stamina, appearance or "is player" flag.
- Intent semantics: `moveX/moveY` is the desired move direction with magnitude 0..1 (larger values are clamped to 1 by movement). `aimX/aimY` is an aim offset from the character in world px. `buttons` is a bitfield whose bits CMB-001 defines. CHR-001 never writes Intent after spawn and never reads aim or buttons. The doc comment on the Intent schema says this.

### Movement system (`sim/src/movement.ts`, new)
```ts
export const WALK_SPEED = 80; // px/s = 5 tiles/s (OQ-025), tunable
/** Applies every character's Intent for the tick that produces snapshot `tick`. */
export function stepMovement(world: CharacterWorld, tick: number): void;
```
For each entity with Position, Velocity, Intent, Facing and Action, in `each` order. Only `+ - * /` and `Math.sqrt`/`Math.abs` are used, because they are exactly rounded and so bit-identical across JS engines:
1. `mx, my` = intent. `len2 = mx*mx + my*my`. If `len2` is not finite, throw a `RangeError` naming the entity id.
2. `scale = len2 > 1 ? WALK_SPEED / Math.sqrt(len2) : WALK_SPEED`; `vx = mx*scale`, `vy = my*scale`. This gives instant acceleration and normalised diagonals, and keeps sub-unit stick magnitudes.
3. `x += vx / TICK_HZ`, `y += vy / TICK_HZ`. Divide by `TICK_HZ` and don't multiply by a `dt` constant, so a cardinal walk is exactly 4 px per tick.
4. Facing from the velocity: if `|vx| > |vy|`, Right when `vx > 0`, else Left. If `|vy| > |vx|`, Down when `vy > 0`, else Up (y-down). Otherwise (an exact diagonal tie, or idle) keep the previous facing.
5. `next = (vx !== 0 || vy !== 0) ? Walk : Idle`. If `next` differs from the current state, set state = `next` and start = `tick`.
No collision (WLD-004), sprint, attack or dodge (CMB-001), and characters don't block each other (OQ-025).

### Sim (`sim/src/sim.ts`)
- `createSim(seed)` keeps its signature. It throws a `RangeError` unless `seed` is an integer in 0..4294967295, which is the same range `main.ts` accepts. That is the seed's only use until world generation consumes it.
- It builds `new World()`. There is no reserved entity: the player may be id 0, and "no player" is `you = -1`.
- `const world = createCharacterWorld(ecs)`; `player = spawnCharacter(world, { x: 0, y: 0, species: Species.Human, tick: 0 })`. **No NPC is spawned.** Sharing is structural: one spawn path, and one system with no player branch. The movement test drives two characters through the same path.
- `step()`: `tick += 1; stepMovement(world, tick);`, in that order, so `actionStart` is the tick of the first snapshot that shows the action.
- `snapshot()` lists every entity with Position, Kind, Facing, Action and Species, in `each` order. It fills all columns and sets `you = player`. Update the `Sim.snapshot` doc comment to say which entities are listed.
- Delete `sim/src/debug-movers.ts`. Remove the now-unused `rng` import from sim.ts.

## Acceptance criteria
- AC1 One spawn path, one movement rule for every character — proven by: test "movement: walks 80 px/s on an axis, the same speed on a diagonal, and keeps sub-unit stick magnitudes" (two or more characters made by `spawnCharacter`, Intent written directly). After 20 `stepMovement` calls, intent (1,0) gives x === 80 and y === 0 exactly. Intent (−1,1) gives `Math.hypot(x, y)` within 1e-9 of 80. Intent (0.5,0) gives x === 40.
- AC2 Facing and action rules — proven by: test "movement: facing follows the dominant axis and holds on exact diagonals and when idle; action is Walk/Idle with actionStart at the change tick". Sequence: spawn (Down, Idle, start 0) → (1,0) at tick 1 → Right, Walk, start 1 → (1,1) → still Right → (0,−1) → Up → (0,0) at tick 4 → Up, Idle, start 4.
- AC3 The sim spawns the player and names it — proven by: test "createSim spawns one Human character at (0,0) and `you` names it": count 1, `you !== -1`, `ids[0] === you`, kind Character, species Human, facing Down, action Idle, x = y = 0.
- AC4 The transfer list covers every column — proven by: test "snapshotBuffers transfers every snapshot column". For every value in the snapshot that is an `ArrayBuffer` view: its `length === count` and its `buffer` is in `snapshotBuffers(s)`, checked by identity (`toContain`, not deep equality). `snapshotBuffers(s).length` equals the number of columns.
- AC5 Discrete columns follow the entity, not the array position — proven by: the existing interpolate test "lerps by id when entity order differs between prev and curr", extended so that each entity has distinct facing/action/actionStart/species in prev and curr, and `out` holds curr's values for that id.
- AC6 Scaffolding is gone — proven by: `grep -rnE "debug-movers|DebugMover|mover32|MOVER_AREA|TilingSprite" sim client/src tools/art CLAUDE.md --exclude-dir=node_modules --exclude-dir=__pycache__` → no matches (exit 1). The built atlas's `debug/` frames are exactly `debug/checker16` and `debug/character32` (the node one-liner below).
- AC7 The page boots and shows the character — proven by: `node scripts/check-page.mjs http://localhost:4191/ /tmp/chr001.png 2000` → exit 0, `"canvas": true`, `"errors": []`. The screenshot shows the placeholder figure standing with its feet at the canvas centre (640, 360), no checker backdrop, and the debug text top-left.
- AC8 Each new test guards something — proven by: the worker's report shows each test failing when its guarded behaviour is broken, then reverted. AC1: drop the `len2 > 1` clamp. AC2: break the tie rule. AC3: set `you` to -1 instead of the player's id (not 0: the player is id 0). AC4: drop one buffer from `snapshotBuffers`. AC5: copy facing from prev's row.
- AC9 Typecheck, lint, tests and build clean — proven by: `npm run check && npm test && npm run build` → exit 0.
