# TEC-021: Parallel startup and a lossless WebP atlas

GDD: docs/gdd/01-tech.md — "**TEC-021** `[proto]` Cut the startup waterfall: start the sim worker in parallel with the atlas load, and reduce Pixi's chunk fan-out; target first frame ≤ 2 s on emulated slow 4G + 4× CPU (found in M0 E2E: 2.65–2.79 s). (OQ-023)". This PR rewrites that line per OQ-028 (text under "GDD edits").
Milestone: M1   Depends on: CMB-001 (merged #20), WLD-003 (the chunk messages this task must queue), TEC-020 (the first-frame mark, `scripts/measure-startup.mjs`, `docs/perf.md` with the "before" row, and its edits to `client/src/main.ts`). All must be merged before dispatch.
Model: sonnet — because the startup order, the early-message queue, the WebP save options and the measuring recipe are locked below and were prototyped on main a137bd1 (WebP rebuilds verified byte-identical); the chunk fan-out question was settled by measurement while drafting.
Branch: tec-021-startup

## Desired result
The page starts the sim worker first, then the renderer and the atlas load together, instead of renderer → atlas → worker. Chunk messages that arrive before the ground layer exists are kept and applied in order, so no ground is ever missing. The art pipeline writes the atlas image as lossless WebP (127 KB instead of the 307 KB PNG), byte-identical across rebuilds, and stops writing a PNG. The first frame on the locked slow-4G phone profile is **≤ 3 s** (the M1 bar, OQ-028; drafting measurement 2.64 s, down from 4.89 s). `docs/perf.md` records the numbers; the GDD records OQ-028 and moves the 2 s target to TEC-012.

## Locked design

### Numbers this design is built on (measured while drafting, main a137bd1 = CMB-001 + ART-006, before WLD-003 and TEC-020; phone 390×844 DPR 3, slow 4G, 4× CPU, cold, vite preview with gzip; ms since navigation start; "first frame" = first ticker frame that drew a snapshot)
| Variant | Atlas | Resolution at DPR 3 | First frame, median (min–max), runs |
|---|---|---|---|
| main (renderer → atlas → worker) | PNG 307 KB | 3 | **4892** (4686–4946), 3 |
| worker first, then `Promise.all([app.init, loadCoreAtlas()])` | PNG | 3 | 3375 (3365–3447), 5 |
| same + static `import "pixi.js/browser"` | PNG | 3 | 3417 (3388–3432), 5 |
| same + `import "pixi.js/browser"` + `skipExtensionImports: true` | PNG | 3 | 3584 (3540–3616), 5 |
| same + one JS bundle (`codeSplitting: false`, 2 JS files) | PNG | 3 | 3659 (3659–3688), 3 |
| **worker first + `Promise.all` + TEC-020's cap (this spec)** | **WebP 127 KB, built by the patched pipeline** | 1.5 | **2638** (2608–2773), 5 |

- Waterfall of the chosen order: `index.html` (0.16 s) → index.js + 10 modulepreloaded Pixi chunks in parallel (≈ 1.07 s) → in parallel: the lazy WebGL renderer chunk and `core.json` (14 KB gzipped) → the atlas image (fetched by Pixi's image worker) → decode, upload, first frame.
- Bytes on the wire with WebP: JS ≈ 150 KB, `core.webp` 127 430 B, `core.json` 14 KB, worker ≈ 4 KB → ≈ 295 KB, ≈ 1.5 s at 200 000 B/s. With the PNG it was ≈ 475 KB, ≈ 2.4 s, so ≤ 2 s was out of reach by bytes alone. 2 s now belongs to TEC-012 (OQ-028).
- **Pixi's chunk fan-out is not on the critical path** once the atlas loads in parallel: static chunks already download in parallel (modulepreload), and the one lazy level (WebGL renderer) finishes while the atlas is still downloading. Every fan-out reduction tried was neutral or slower. The 24 files on disk include lazy WebGPU and Canvas renderer chunks that are never requested in WebGL browsers. **Locked: no Vite or Pixi import/chunking change.**
- `Assets.load` of the spritesheet works before `app.init` finishes (`pixi.js`'s main entry registers the spritesheet loader).
- **WebP is byte-stable.** Pillow 12.3.0 (bundled libwebp 1.6.0, the pinned `tools/art/requirements.txt`), patched `write_atlas`, three full `tools/art/build.py` runs: default; `PYTHONHASHSEED=random`; from `/tmp` with `TZ=Asia/Tokyo PYTHONHASHSEED=7` → `cmp` on `core.webp` and `core.json` silent for all pairs, `BYTE-IDENTICAL`, sha256 `ccf1ef48…3c3c` for all three. Decoding the WebP gives the PNG's RGBA bytes exactly (lossless). Pillow lossless sizes: 127 430 B for `quality=100, method=6` and `quality=100, method=4`; `quality=80, method=4` is 129 628 B.
- **Pixi 8 loads it with no client change.** Headless Chromium: `core.webp` requested (127 430 B), the spritesheet parses, the character frame draws, 0 errors (Pixi's texture loader accepts `.webp`; Safari ≥ 14 and every current Chromium/Firefox decode lossless WebP).

### Startup order (`client/src/main.ts`)
Locked order and behaviour; the exact code shape is the worker's within this:
```ts
// Pixel art: …                                  (unchanged, still before any texture exists)
TextureStyle.defaultOptions.scaleMode = "nearest";
const maxDpr = maxDprFromUrl();                  // TEC-020, unchanged

// Everything the worker's message handler touches is declared before the worker exists:
// a message can arrive while app.init or the atlas is still pending.
let app: Application | null = null;
let ground: ChunkLayer | null = null;
/** Chunk messages that arrived before the ground layer existed, in arrival order. */
const early: ChunkStreamMessage[] = [];
let prev / curr / currReceivedAt …;  let chunksAdded = 0;  let worker: Worker | null = null;

try {
  worker = new Worker(new URL("./sim-worker.ts", import.meta.url), { type: "module" });
  worker.addEventListener("message", …);          // see "Message handler"
  worker.addEventListener("error", …);            // unchanged text
  worker.postMessage({ type: "init", seed: seedFromUrl() } satisfies HostToSim);

  app = new Application();
  const [, sheet] = await Promise.all([app.init({ …TEC-020's options, unchanged… }), loadCoreAtlas()]);
  if (fatal) { worker.terminate(); app.destroy(); }   // the sim already failed while we waited: keep its message
  else { /* exactly today's renderer setup, in today's order: pixelated, appendChild, watchDpr, requireFrames,
            world, ground = new ChunkLayer(…), then flush `early` (below), view, debugText, ticker, ?perf, input */ }
} catch (error) {
  worker?.terminate();
  showFatal("overgrown couldn't start the renderer", error);
}
```
- **Flush:** right after `ground = new ChunkLayer(world, sheet, app.renderer)`, apply every message in `early` in order through the same function the handler uses, then `early.length = 0`.
- **Message handler:** the WLD-003 exhaustive switch stays. `snapshot` → as today (it needs no renderer). `chunk` and `unchunk` → one function `applyChunkMessage(msg)`: if `ground === null` push to `early`, else `ground.add(msg)` + `chunksAdded += 1` / `ground.remove(msg.cx, msg.cy)`. `error` → `showFatal` as today. On a throw: stop `app`'s ticker if `app` exists, terminate the worker, `showFatal("overgrown couldn't draw the world", error)` (today's text).
- **`showFatal` keeps the first message:** add `let fatal = false`; `showFatal` always `console.error`s, but only the first call writes the page text and sets `fatal = true`. Reason: with the worker started first, a sim failure can now land before the renderer is up, and the follow-on renderer error must not overwrite the real cause.
- The first-frame mark (TEC-020) is unchanged; replayed chunks count through `applyChunkMessage`. The camera, the ticker body, `?perf`, `watchDpr`, input wiring and all error texts stay as TEC-020 left them.
