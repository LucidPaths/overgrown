# CMB-001: Desktop input, attack/dodge/sprint actions and the follow camera

GDD: docs/gdd/05-combat.md — "**CMB-001** `[proto]` Desktop input: WASD movement, mouse aim, LMB attack, Space dodge, Shift sprint. M1: attack, dodge and sprint are animation-only with no stamina (OQ-021); movement and facing defaults in OQ-025."
Milestone: M1   Depends on: CHR-001 (components, `spawnCharacter`, `stepMovement`, snapshot `you`, the `world` container), WLD-001 (`TILE_PX` in `sim/src/constants.ts`). Runs in parallel with WLD-002 (`sim/src/world/**`) and ART-004 (`tools/art/**`); no file overlap.
Model: opus — because the input message becomes the TEC-010 net input, the Intent button bits and the action state machine are shared with NPC-001 and CMB-002, and the camera's pixel rules are what WLD-003 and CMB-002 build on.
Branch: cmb-001-desktop-input

## Desired result
On desktop, WASD (or the arrow keys) walks the local character, Shift sprints at ×1.6, LMB plays a rooted 0.4 s attack facing the mouse, and Space rolls 48 px. All of it travels as one `input` message that the sim latches into the `you` character's Intent at tick start, and the same action rules apply to every character. The camera follows the `you` character at the largest integer device-pixel scale that shows ≥ 16 tiles on the short axis, with the camera and every sprite snapped to whole art pixels, so nothing jitters at any devicePixelRatio.

## Locked design

### Protocol (`sim/src/protocol.ts`): the input contract
Add, and widen `HostToSim`:
```ts
/**
 * The local player's full input state, posted by the host whenever it changes. The sim latches the newest
 * one at the start of each tick. This shape becomes the TEC-010 network input message.
 */
export interface InputMessage {
  type: "input";
  /** Desired move direction, each axis in [-1, 1]. The sim clamps the magnitude to 1 (so W+D is a normal diagonal). */
  moveX: number;
  moveY: number;
  /** Aim point as an offset from the character's feet point, in world px (y-down). (0, 0) means "no aim". */
  aimX: number;
  aimY: number;
  /** Sprint is held. (Attack and dodge are edge actions: only their press counters are sent.) */
  sprint: boolean;
  /** Presses since the host started: u32, starting at 0, +1 per press, wrapping at 2^32. A changed value means "pressed". */
  attackPresses: number;
  dodgePresses: number;
}
export type HostToSim = { type: "init"; seed: number } | InputMessage;
```
`SimToHost` and `Snapshot` are unchanged.

### Input latch (`sim/src/input.ts`, new)
```ts
export interface InputLatch { latest: InputMessage | null; attackSeen: number; dodgeSeen: number }
/** latest = null; both seen counters 0, matching the host's starting counters. */
export function createInputLatch(): InputLatch;
/** Throws a RangeError naming the first invalid field and its value. */
export function assertInputMessage(msg: InputMessage): void;
/** Tick start: writes `latch.latest` into character `id`'s Intent. No-op until the first message. */
export function latchInput(latch: InputLatch, world: CharacterWorld, id: EntityId): void;
```
- `assertInputMessage` accepts exactly: `moveX`, `moveY` finite and in [-1, 1]; `aimX`, `aimY` finite; `sprint` a boolean; `attackPresses`, `dodgePresses` integers in 0..4294967295. Anything else is a RangeError (this is the boundary that becomes network-facing in TEC-010).
- `latchInput` writes `moveX/moveY/aimX/aimY` as given (movement clamps the magnitude), and
  `buttons = (sprint ? Sprint : 0) | (buttons & (AttackPress | DodgePress)) | newPresses`, where `newPresses` sets `AttackPress` iff `latest.attackPresses !== attackSeen` (likewise dodge). Then `attackSeen/dodgeSeen = latest's counters`. Keeping the existing press bits is what lets a buffered press survive (see Actions). `latest` stays set, so move, aim and sprint persist until the next message.
- Consequences (locked): a press and release that both happen between two ticks is still one press. Several presses between two ticks collapse into one. The same message latched again on later ticks adds no press.

### Actions (`sim/src/actions.ts`, new)
```ts
export const ATTACK_TICKS = Math.round(0.4 * TICK_HZ);   // 8 at 20 Hz; 0.4 s tunable (OQ-021)
export const DODGE_TICKS = Math.round(0.35 * TICK_HZ);   // 7; 0.35 s tunable (OQ-021)
export const DODGE_DISTANCE = 48;                        // px = 3 tiles, tunable (OQ-021)
export const BUFFER_TICKS = Math.round(0.2 * TICK_HZ);   // 4; press-buffer window, tunable
/** Starts, ends and buffers attack/dodge for every character from its Intent, for the tick that produces snapshot `tick`. */
export function stepActions(world: CharacterWorld, tick: number): void;
```
For each entity with Intent, Action, Facing and Velocity, in `each` order (same arithmetic restriction as movement: `+ - * /`, `Math.sqrt`, `Math.abs` only):
1. **End.** If state is Attack and `tick - start >= ATTACK_TICKS`, or Dodge and `tick - start >= DODGE_TICKS`: state = Idle, start = `tick`. (Movement turns it into Walk with the same start if the character is moving.) So an action started at `s` is shown by snapshots `s .. s+D-1`.
2. **Start** (only if state is Idle or Walk). Dodge wins over attack when both press bits are set.
   - Dodge: `len2 = mx*mx + my*my` from the move intent, `a2 = aimX*aimX + aimY*aimY` (RangeError naming the entity if either is not finite). Roll direction = `(mx, my) / Math.sqrt(len2)` if `len2 > 0` (full 48 px even for a small stick); else `(aimX, aimY) / Math.sqrt(a2)` if `a2 > 0`; else the facing's unit vector (Down (0,1), Left (−1,0), Right (1,0), Up (0,−1)). Facing = `facingToward(aimX, aimY, facing)` (OQ-025: snap to the aim while attacking or dodging; no aim keeps the facing), independent of the roll direction. Velocity = direction × `DODGE_DISTANCE * TICK_HZ / DODGE_TICKS`. State = Dodge, start = `tick`. Clear `DodgePress`.
   - Attack: facing = `facingToward(aimX, aimY, facing)`. State = Attack, start = `tick`. Clear `AttackPress`.
3. **Buffer.** Then, if the state is Attack or Dodge, each press bit still set is cleared unless the current action ends within the window: keep it iff `start + duration - tick <= BUFFER_TICKS`. A kept bit starts its action on the tick the current one ends (step 1 then step 2). In any other state (Hurt/Death, never set in M1) press bits are cleared.
   - Why buffered, not dropped: input reaches the sim 1–3 ticks late (A-19), so a press made just before the swing visibly ends would otherwise vanish; the 0.2 s window stops a press early in an action from firing an unwanted action much later. The press bit itself is the buffer, so no new component or state is needed.

### Movement (`sim/src/movement.ts`, extended)
- Export the CHR-001 facing rule as `export function facingToward(dx: number, dy: number, current: FacingValue): FacingValue` (dominant axis; exact tie, including (0,0), keeps `current`). Movement step 4 calls it. If CHR-001 already has an equivalent private helper, export and rename that one; there must be one copy of the rule.
- Add `export const SPRINT_MULTIPLIER = 1.6; // OQ-021, tunable` next to `WALK_SPEED`.
- Per character, the CHR-001 steps change only like this:
  - **Idle/Walk:** steps 1–5 as CHR-001, except step 2's speed is `WALK_SPEED * SPRINT_MULTIPLIER` when `buttons & IntentButton.Sprint`, else `WALK_SPEED` (the clamp and sub-unit magnitudes are unchanged, so a full stick + sprint = 128 px/s and sprint without movement does nothing).
  - **Dodge:** keep the velocity stepActions set (move intent is ignored), integrate it (step 3), skip steps 4–5.
  - **Any other state (Attack; Hurt/Death later):** velocity = 0, skip steps 4–5 (rooted, facing held).
- Sprint is still Action Walk. No collision (WLD-004).

### Sim (`sim/src/sim.ts`)
- `Sim` gains `input(msg: InputMessage): void` — "Validates `msg` (RangeError naming the field) and keeps it as the newest input for the local player's character; the next step() latches it." It calls `assertInputMessage` then sets `latch.latest = msg`.
- `step()`: `tick += 1; latchInput(latch, world, player); stepActions(world, tick); stepMovement(world, tick);` in that order. The latch is the only player-specific line in the sim: `actions.ts` and `movement.ts` never mention the player.

### Worker (`client/src/sim-worker.ts`)
- Keep the created `Sim` in a module-level `let sim: Sim | undefined` (set in `start`).
- `case "input":` → if `sim === undefined` throw `Error("sim worker got input before init")`, else `sim.input(msg)`. Errors go through the existing `fail`.

### Camera (`client/src/render/camera.ts`, new, pure: no DOM, no Pixi)
```ts
/** OQ-024: the short axis shows at least this many tiles. Tunable. */
export const MIN_VIEW_TILES = 16;
/** Device px per art px: the largest integer keeping ≥ MIN_VIEW_TILES tiles on the short axis; at least 1.
 *  RangeError unless both sizes are integers ≥ 0. */
export function integerScale(deviceW: number, deviceH: number): number;
//   = Math.max(1, Math.floor(Math.min(deviceW, deviceH) / (MIN_VIEW_TILES * TILE_PX)))
export interface CameraLayout {
  scale: number;    // integer ≥ 1, device px per world px
  anchorX: number;  // device px where the camera target is drawn: Math.floor(deviceW / 2)
  anchorY: number;  // Math.floor(deviceH / 2)
  originX: number;  // device px where world (0,0) is drawn: anchorX - Math.round(targetX) * scale (an integer)
  originY: number;
}
/** Follow camera: the target, rounded to whole world px, lands on the anchor device pixel. No smoothing (A-18). */
export function layoutCamera(deviceW: number, deviceH: number, targetX: number, targetY: number): CameraLayout;
/** World-px offset of a device-px point from the camera target: ((x - anchorX) / scale, (y - anchorY) / scale). */
export function deviceToTargetOffset(layout: CameraLayout, deviceX: number, deviceY: number): { x: number; y: number };
```

### Renderer and pixel rules (`client/src/main.ts`, `client/src/render/snapshot-view.ts`)
- Pixi init stays `resizeTo: window, autoDensity: true, resolution: window.devicePixelRatio || 1`. Pixi sizes the backing store to `Math.round(cssSize * resolution)` device px and sets the CSS size to `backing / resolution`, so one stage unit is exactly `resolution` device px even for DPR 2.625. TEC-020 caps `resolution` at that one call; everything below reads the actual backing size and resolution, so a cap needs no other change.
- **Amendment (orchestrator, after the worker's measurement):** with a non-integer DPR, Pixi's CSS size `backing / resolution` can be fractional (e.g. 412.19 px at 2.625). The browser then composites the backing store bilinearly into ~1 device px less, which blends pixels. So `main.ts` also sets `app.canvas.style.imageRendering = "pixelated"` once after init, and the compositor stays nearest-neighbour. Exact device-pixel sizing via ResizeObserver `device-pixel-content-box` is left to TEC-020.
- Ticker, after `interpolate` and before `view.update`:
  1. `const i = frame.ids.subarray(0, frame.count).indexOf(frame.you)`; if `i >= 0` the target is `(frame.x[i], frame.y[i])`, else keep the last target (initially (0, 0)).
  2. `layout = layoutCamera(app.canvas.width, app.canvas.height, targetX, targetY)` (device px).
  3. `const r = app.renderer.resolution; world.scale.set(layout.scale / r); world.position.set(layout.originX / r, layout.originY / r);` — this replaces CHR-001's fixed screen-centre line and its comment.
  4. `input.setLayout(layout)`.
- `snapshot-view.ts`: `sprite.position.set(Math.round(x), Math.round(y))`, with a one-line comment: whole art px × integer scale + integer origin = every texel on whole device pixels (10-art-audio: no sub-pixel jitter). The camera target is rounded the same way, so the local character never wobbles against the camera.
- `debugText` stays on the stage in CSS units, unaffected by the camera.

### Keyboard and mouse adapter (`client/src/input/keyboard-mouse.ts`, new)
```ts
export class KeyboardMouseInput {
  /** Attaches the listeners below. `post` receives a fresh InputMessage whenever any field changes. */
  constructor(canvas: HTMLCanvasElement, post: (msg: InputMessage) => void);
  /** Called every frame with the camera in use; re-derives the aim only if scale or anchor changed. */
  setLayout(layout: CameraLayout): void;
}
```
- Keys by `KeyboardEvent.code` (layout-independent): up `KeyW`/`ArrowUp`, left `KeyA`/`ArrowLeft`, down `KeyS`/`ArrowDown`, right `KeyD`/`ArrowRight`, sprint `ShiftLeft`/`ShiftRight`, dodge `Space`. Arrow keys are included as aliases (accessibility, left-handed play, zero conflicts). Held codes live in a `Set`; a direction is held if either of its codes is.
- `moveX = right − left`, `moveY = down − up` (each 0/±1; opposite keys cancel; the sim normalises diagonals).
- `keydown` on `window`: ignore unbound codes. For bound codes: `preventDefault()` only for `Space` and the four arrows (scrolling/button activation). Then ignore if `ctrlKey || metaKey || altKey` (browser shortcuts; on macOS a Meta-held key never sends keyup, so it would stick) or `repeat`. Else add the code; on `Space`, `dodgePresses = (dodgePresses + 1) >>> 0`. `keyup` on `window`: `preventDefault()` for Space/arrows, delete the code (always, regardless of modifiers).
- Mouse on the canvas, `pointerType` `"mouse"` or `"pen"` only (touch is CMB-002): on `pointerdown`, `pointermove`, `pointerup`, `pointercancel` store `clientX/clientY` and recompute the aim; LMB held = `(event.buttons & 1) !== 0` (works for button chords, where a second button sends `pointermove`, not `pointerdown`). LMB held is internal edge-detection state, not sent. A 0→1 transition of it does `attackPresses = (attackPresses + 1) >>> 0`. `pointerdown` with LMB calls `canvas.setPointerCapture(event.pointerId)` so the release is seen outside the canvas. `contextmenu` on the canvas: `preventDefault()` (RMB is reserved for block/aim). No other default is prevented.
- Aim: device px of the pointer = `(clientX − rect.left) × canvas.width / rect.width` (same for y with height), then `deviceToTargetOffset(layout, …)`. Aim is (0, 0) until both a pointer position and a layout exist. Because the camera is centred on the character with no smoothing, the aim only changes when the mouse moves or the layout changes, not while walking.
- `blur` on `window`, and `visibilitychange` on `document` when `document.visibilityState === "hidden"`: clear held codes (move and sprint) and the internal LMB-held flag. Counters are not reset.
- Posting: after every handled event and in `setLayout`, build the message and post it only if any of its 7 fields differs from the last posted one (counters make every press a change).
- `main.ts` constructs it after posting `init`: `new KeyboardMouseInput(app.canvas, (msg) => worker.postMessage(msg))`.

## Acceptance criteria
- AC1 A press is applied exactly once and never lost — proven by: `sim/src/sim.test.ts` test "input: a press between ticks is applied exactly once, and several presses between ticks are one press". Via `createSim` + `sim.input`: post `{attackPresses: 1}` then `{attackPresses: 1, moveX: 1}` before one `step()` (the press survives being superseded by a later message) → snapshot action Attack, actionStart 1. Over the next 20 steps, the set of `actionStart` values seen while action is Attack is exactly `{1}`. Then post `{attackPresses: 3}` → exactly one new Attack episode over 20 steps. import { chromium } from "playwright-core";

const URL = "http://localhost:4194/";
const errors = [];
const near = (a, b, tol) => Math.abs(a - b) <= tol;

// Runs in the page before app code: records posted input messages and the `you` row of each snapshot.
function instrument() {
  const Base = window.Worker;
  window.__inputs = [];
  window.__you = null;
  window.Worker = class extends Base {
    constructor(...args) {
      super(...args);
      this.addEventListener("message", (e) => {
        const s = e.data && e.data.snapshot;
        if (!s) return;
        const i = s.ids.indexOf(s.you);
        if (i >= 0) window.__you = { tick: s.tick, x: s.x[i], y: s.y[i], facing: s.facing[i], action: s.action[i] };
      });
    }
    postMessage(msg, transfer) {
      if (msg && msg.type === "input") window.__inputs.push(msg);
      return transfer === undefined ? super.postMessage(msg) : super.postMessage(msg, transfer);
    }
  };
}

async function open(browser, options) {
  const page = await browser.newPage(options);
  page.on("pageerror", (e) => errors.push(`pageerror: ${e.message}`));
  page.on("console", (m) => { if (m.type() === "error") errors.push(`console: ${m.text()}`); });
  await page.addInitScript(instrument);
  await page.goto(URL);
  await page.waitForFunction(() => window.__you !== null, null, { timeout: 5000 });
  return page;
}

const r = {};

  async function hold(keys) {

    const a = await you();
    await page.waitForTimeout(500);
    const b = await you();

    return { dx: (b.x - a.x) / dt, dy: (b.y - a.y) / dt, facing: b.facing, action: b.action };

  await waitAction(0);

    const menu = new MouseEvent("contextmenu", { bubbles: true, cancelable: true });
