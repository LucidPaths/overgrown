## Desired result

Every cloud session and every CI run gets a working Godot 4.7.2, plus Blender 4.5.14 LTS for the art tasks, without anyone doing anything.

`game/` is a Godot 4 project that opens cleanly. A minimal test runner gives real exit codes, so later tasks can add GDScript tests the same way they added vitest tests.

## Locked design

1. **`tools/godot/setup.sh`.** Derived from the spike's `setup.sh`.
   - Pinned versions: Godot 4.7.2-stable and Blender 4.5.14 LTS, each checked against its SHA, plus the Mesa, Xvfb and runtime libraries via apt.
   - Idempotent. A rerun with everything already installed returns in under 5 s, so skip apt when the packages are present.
   - Flags:
     - `--no-blender` skips Blender, for CI and quick sessions.
     - `--templates` also downloads and installs the matching Godot export templates, `Godot_v4.7.2-stable_export_templates.tpz`, from the same GitHub release, SHA checked, into `~/.local/share/godot/export_templates/4.7.2.stable/`. GOD-002 uses it.
   - It prints the versions at the end.
   - It must work as root in the cloud container and on GitHub's `ubuntu-latest`, using `sudo` when not root.
2. **SessionStart hook.** Add `.claude/settings.json` (none exists today):
   ```json
   {"hooks":{"SessionStart":[{"hooks":[{"type":"command","command":"[ \"$CLAUDE_CODE_REMOTE\" = \"true\" ] && bash \"$CLAUDE_PROJECT_DIR/tools/godot/setup.sh\" >/tmp/godot-setup.log 2>&1 || true"}]}]}
   ```
   - It runs only in cloud sessions and never blocks or fails the session.
   - The log goes to `/tmp/godot-setup.log`.
   - Blender is included. It costs about 10 s, and art tasks need it.
3. **`game/`, the Godot project (4.7, Forward+).**
   - `project.godot`:
     - name `overgrown`;
     - main scene `res://scenes/main.tscn`;
     - window 1280×720, resizable;
     - `rendering/renderer/rendering_method="forward_plus"`;
     - application icon left at the default.
   - `scenes/main.tscn` + `scenes/main.gd`: a placeholder. A camera at the tilted ARPG angle (PLAN D4: about 50° pitch) looks at a ground plane with a DirectionalLight3D (shadows on) and a WorldEnvironment (procedural sky, fog off). The scene also shows a centred Label "overgrown: G0 scaffold" and the build version.
   - **Version:** `game/version.gd` is a `class_name GameVersion` with `const VERSION := "0.1.0"`. That is the single source; GOD-002 adds the commit hash.
   - **Capture mode:** `main.gd` honours `-- --capture <png> [--frames N]`. It renders N warm-up frames (default 5), saves the viewport to the PNG and quits with 0. A watchdog timer quits with 2 after 60 s.
   - Folders: `src/` (GDScript classes, empty except `.gitkeep`), `tests/`, `assets/`.
   - `.gitignore`: add `game/.godot/`, `game/export/` and `*.import` caches as appropriate. Imported `.import` sidecar files for committed assets *are* committed per Godot convention; the `.godot/` cache isn't.
4. **Test runner.** `game/tests/run.gd` is a `SceneTree` script.
   - It finds every `game/tests/test_*.gd`, instantiates each, and calls every method whose name starts with `test_`.
   - A test fails by calling `t.fail("msg")` on a small `TestContext` passed in, or by raising an error the runner can detect. Prefer the context; GDScript has no exceptions.
   - It prints `PASS`/`FAIL file::method` lines and a summary, and quits with 0 when all pass and 1 otherwise, including when a test script fails to load or parse.
   - Add `game/tests/test_scaffold.gd` with two real checks:
     - `GameVersion.VERSION` matches `^\d+\.\d+\.\d+$`;
     - `main.tscn` loads and instantiates with a Camera3D whose pitch is between 40° and 60°.
5. **`tools/godot/test.sh`.**
   - Runs `godot --headless --path game --import`. A failed import exits non-zero.
   - Then runs `godot --headless --path game --script res://tests/run.gd`.
   - Exits with the runner's code.
6. **`tools/godot/capture.sh <out.png> [renderer]`.**
   - `xvfb-run -a -s "-screen 0 1280x720x24" godot --path game --audio-driver Dummy --rendering-method <forward_plus|gl_compatibility> -- --capture <out.png>`
   - A 120 s timeout. It exits non-zero if the PNG is missing.
7. **CI.** Add a second job, `godot`, to `.github/workflows/ci.yml`:
   - `ubuntu-latest`;
   - `actions/cache` on the Godot install (key = version);
   - `tools/godot/setup.sh --no-blender`;
   - `tools/godot/test.sh`.

   The existing `ci` job stays untouched; it is retired in OVR-010.

Delegated micro-decisions: the internal structure of the runner and the setup script, helper names, label styling.

## Acceptance criteria
- **AC1 Setup works and is idempotent.** Ran `bash tools/godot/setup.sh` → versions printed (Godot 4.7.2, Blender 4.5.14). A second run takes under 5 s (`time`). `bash tools/godot/setup.sh --no-blender --templates` installs the templates (`ls ~/.local/share/godot/export_templates/4.7.2.stable/`).
- **AC2 Tests have real exit codes.** `bash tools/godot/test.sh` → all PASS, exit 0. Two temporary breaks must fail, then be reverted:
  - a failing assertion → exit 1;
  - a parse error in a test file → exit 1.
- **AC3 Capture works.** `bash tools/godot/capture.sh /tmp/g001.png` → exit 0. View the PNG and report one line on what it shows: tilted camera, lit plane, label.
- **AC4 Hook is valid.** `.claude/settings.json` parses as JSON. Running its command by hand with `CLAUDE_CODE_REMOTE=true CLAUDE_PROJECT_DIR=$PWD` → exit 0 and a log written. With `CLAUDE_CODE_REMOTE` unset → exit 0, nothing run.
- **AC5 Repo checks still pass.** `npm run check && npm test` → exit 0. First run `source /home/user/overgrown/.venv/bin/activate` on its own line.
- **AC6 CI is green.** The orchestrator verifies this on the PR: both the `ci` and `godot` jobs pass.
