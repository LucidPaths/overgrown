# ART-005: Character body generator, 9 species on one skeleton, 4 directions

GDD: docs/gdd/10-art-audio.md — "Character body generator per species body plan, 4 directions. All 9 species share one humanoid skeleton and differ by parameters; new actor palette (OQ-020, OQ-027)."
Milestone: M1   Depends on: none (ART-001, ART-002, ART-003 are merged)
Model: opus — the skeleton and species table are the contract that ART-006, ART-009 and ART-010 build on, and the art has to read well at 32 px.
Branch: art-005-body-generator

## Desired result
The pipeline emits a base idle pose for all 9 species in 4 directions (`actor/<species>/idle/<dir>/0`, 36 frames in the `core` atlas). All of them are drawn from one shared humanoid skeleton whose named anchor joints live in a Python data structure that later generators reuse. Species differ only through a data table, colours come only from the new validated `actors` palette, and right-facing frames are exact mirrors of the left-facing ones. A rebuild is byte-identical.

### `lib/skeleton.py`
```python
CELL = 32                 # actor frames are CELL x CELL
CENTRE_X = 16.0           # continuous centre line of the cell (between columns 15 and 16)
SOLE_Y = 29               # every foot joint sits on this row; the outline puts the lowest opaque row at SOLE_Y + 1
DIRECTIONS = ("down", "left", "right", "up")   # the contract's dir keys
JOINTS = ("head", "neck", "shoulder_l", "shoulder_r", "hand_l", "hand_r",
          "hip_l", "hip_r", "foot_l", "foot_r", "tail_root")

@dataclass(frozen=True)
class Point:
    x: int
    y: int                # pixel indices in the cell, y down

@dataclass(frozen=True)
class Skeleton:
    joints: dict[str, Point]          # exactly the JOINTS keys; treat as immutable (derive with dataclasses.replace)
    near: Literal["l", "r"] | None    # side facing the camera in profile views; None for down and up
    def __post_init__(self) -> None:  # ValueError naming the joint if a key is missing or extra, a coordinate
                                      # is not an int, or a point lies outside 1..CELL-2 on either axis
    def __getitem__(self, joint: str) -> Point
    def mirrored(self) -> "Skeleton": # x -> CELL-1-x for every joint, swap every _l/_r joint name, swap near

def base_skeleton(species: Species, direction: str) -> Skeleton   # ValueError for an unknown direction
```
- **`_l` and `_r` always mean the character's own left and right**, never the screen's. When facing down, `hand_r` is on screen-left. When facing up, it is on screen-right. When facing left, the character's left side faces the camera, so `near = "l"`. ART-009 puts the main-hand weapon on `hand_r` and relies on this.
- `head` is the centre of the head box. `neck` is the single neck row. The `shoulder_*`, `hand_*`, `hip_*` and `foot_*` joints are the joint pixels: `hand_*` is the last pixel of the arm and `foot_*` is the sole contact pixel. `tail_root` is where the tail leaves the body.
- Idle base pose. Arms hang straight down and the feet stand on `SOLE_Y`. Species dimensions come from `Species` (see below).
  - **Rows, the same in every direction:**
    - `foot_*.y = SOLE_Y`
    - `hip_*.y = SOLE_Y - leg`
    - `neck.y = hip.y - torso`
    - `shoulder_*.y = neck.y + 1`
    - `hand_*.y = shoulder.y + arm - 1`
    - `head.y = neck.y - (head_h + 1) // 2`
    - `tail_root.y = hip.y`

    The head box occupies rows `neck.y - head_h .. neck.y - 1`.
  - **down:**
    - `head`, `neck` and `tail_root` have x = 16.
    - `shoulder_r.x = 16 - shoulder` and `shoulder_l.x = 15 + shoulder`.
    - `hand_r.x = shoulder_r.x - 1` and `hand_l.x = shoulder_l.x + 1`.
    - `hip_r.x = 16 - hip` and `hip_l.x = 15 + hip`.
    - `foot_* .x = hip_*.x`.
    - `near = None`.
  - **up:** the same x values as down with the `_l`/`_r` labels exchanged (so `shoulder_r.x = 15 + shoulder`, and so on). `near = None`.
  - **left:** the head, face, snout or beak and the eye point toward smaller x. `tail_root.x >= neck.x + 2` (at the back). `near = "l"`. Every joint stays in 1..30. The exact x offsets are delegated (see below).
  - **right:** exactly `base_skeleton(species, "left").mirrored()`.

### `lib/species.py`
```python
@dataclass(frozen=True)
class Species:
    key: str                      # the contract's species key (frame names)
    leg: int                      # rows from hip to sole
    torso: int                    # rows from neck to hip
    arm: int                      # rows from shoulder to hand, inclusive
    head_w: int
    head_h: int
    shoulder: int                 # half-span of the shoulders from the centre line
    hip: int                      # half-span of the hips
    head_shape: Literal["round", "square"]
    ears: Literal["none", "pointed", "fox", "rabbit", "bear"]
    face: Literal["plain", "tusks", "muzzle", "snout_fox", "snout_bear", "snout_lizard", "beak"]
    tail: Literal["none", "fox", "rabbit", "bear", "lizard"]
    covering: Literal["skin", "fur", "feathers", "scales"]
    hair: Literal["none", "short", "long", "short_beard", "crest"]
    body_ramp: str                # actors ramp for skin, fur, feathers or scales
    accent_ramp: str | None       # snout or muzzle, tail tip or puff, sleeve fringe; None iff covering == "skin"
    hair_ramp: str | None         # None iff hair == "none"
    # __post_init__: ValueError naming key and field for a non-positive dimension, a value outside its
    # Literal set, or a broken None-rule. Geometric fit is NOT checked here (see the cell check in actor.py).

SPECIES: tuple[Species, ...]      # exactly these 9 rows, in this order
```
Starting values. The dimensions are tunable; the feature columns are locked.

|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| human | 7 | 8 | 9 | 10 | 10 | 5 | 4 | round | none | plain | none | skin | short | skin_human | — | hair_brown |
| elf | 8 | 9 | 10 | 9 | 10 | 4 | 3 | round | pointed | plain | none | skin | long | skin_elf | — | hair_blond |
| dwarf | 5 | 8 | 8 | 10 | 10 | 6 | 5 | square | none | plain | none | skin | short_beard | skin_dwarf | — | hair_red |
| orc | 7 | 9 | 10 | 11 | 9 | 6 | 5 | square | pointed | tusks | none | skin | short | skin_orc | — | hair_black |
| foxfolk | 6 | 8 | 9 | 9 | 9 | 4 | 3 | round | fox | snout_fox | fox | fur | none | fur_fox | cream | — |
| bearfolk | 6 | 9 | 10 | 11 | 10 | 7 | 6 | round | bear | snout_bear | bear | fur | none | fur_bear | cream | — |
| rabbitfolk | 6 | 7 | 8 | 9 | 9 | 4 | 3 | round | rabbit | muzzle | rabbit | fur | none | fur_rabbit | cream | — |
| birdfolk | 7 | 8 | 9 | 9 | 9 | 4 | 3 | round | none | beak | none | feathers | crest | feather_bird | cream | feather_bird |
| lizardfolk | 7 | 8 | 9 | 9 | 9 | 5 | 4 | round | none | snout_lizard | lizard | scales | none | scale_lizard | cream | — |

- Dwarf has the shortest standing height (`leg + torso + head_h`) and elf the tallest.
- Bearfolk has the largest `shoulder`.
- Everything, including ears and crest, passes the cell check.

Head-top rows with these values: human 4, elf 2, dwarf 6, orc 4, foxfolk 6, bearfolk 4, rabbitfolk 7, birdfolk 5, lizardfolk 5.

### `gen/actor.py`
```python
NAME = "actor"
ATLAS = "core"
LIGHT = (0.0, -0.6, 0.8)   # straight above and in front, so mirrored right frames keep consistent lighting

def frame_name(species_key: str, anim: str, direction: str, index: int) -> str
    # f"actor/{species_key}/{anim}/{direction}/{index}"; the only place the format is spelled out
def draw_body(ctx: Context, species: Species, skel: Skeleton, direction: str) -> np.ndarray
    # CELL x CELL RGBA, outline applied, cell check passed
def generate(ctx: Context) -> list[Frame]
```

**`draw_body` reads limb positions only from `skel`.** Arms run from shoulder to hand, legs from hip to foot, the head sits at `head`, and the tail starts at `tail_root`. Sizes come from `species`. ART-006 then animates by passing moved joints, without redrawing logic.

**The data drives the drawing; there are no per-species branches.**
- Code branches only on feature fields (`ears`, `face`, `tail`, `covering`, `hair`, `head_shape`), using a dict that maps each feature value to a small draw function, or a short `match`.
- No code outside `lib/species.py` mentions a species key.
- Feature-fixed colours:
  - `beak` → ramp `beak`
  - `tusks` → colour `tusk`
  - inner ears of `fox` and `rabbit` → colour `ear_inner`
  - eyes → colour `eye`

**Layer order (back to front),** matching the GDD paper doll so ART-010 can interleave later:
1. the tail, when it is behind the body (down and side views)
2. the far arm (side views only: the `_r` arm when `near == "l"`)
3. legs and feet
4. torso
5. base clothes:
   - a sleeveless top in ramp `cloth_linen`, rows `shoulder.y .. hip.y`
   - shorts in ramp `cloth_brown`, rows `hip.y + 1 .. hip.y + 2`
   - feet, paws and lower legs stay bare (body covering)
6. arms (both in down and up views, the near arm in side views)
7. the head
8. ears, face and hair (hair stays inside the head box rows, except long hair hanging down behind and the crest above it)
9. the tail, when it is in front (up view)
10. the outline

**Shading.**
- Body parts are bool masks filled with `draw.shade_sphere(img, mask, ramp, light=LIGHT)`.
- Parts at most 2 px wide may use `draw.fill_mask` with one ramp shade.
- `covering` adds a deterministic texture on top of the body ramp:
  - skin: smooth.
  - fur: tufted silhouette edges on the cheeks and tail.
  - feathers: a feathered fringe along the bottom of each arm (Birdfolk arms are arms with feathered sleeves, per OQ-020), plus a 2-shade scallop.
  - scales: an alternating 2-shade pattern on the limbs and tail.
- Use only `draw.py` primitives, Bayer dithering included. No `ctx.rng`, no `random`, no `hash()`: this task has no randomness at all.

**Faces.**
- Down view: 2 eye pixels.
- Side view: 1 eye pixel.
- Up view: no eyes. The back of the head shows hair, fur or feathers.

**Outline.** Applied last: `draw.outline(img, actors.color("outline"))`, 4-adjacent.

**Cell check (Errors Are Answers).** As its last step, `draw_body` raises `ValueError(f"actor {species.key}/{direction}: ...")` naming the problem if either rule breaks:
- any opaque pixel is on the cell's outer ring (row 0, row 31, column 0 or column 31), which means something was clipped;
- the lowest opaque row is not `SOLE_Y + 1`.

`draw.rect` clips silently, so without this check an oversized species would ship cut off.

**`generate`.**
- For each `Species` in `SPECIES`, it draws `down`, `left` and `up` from `base_skeleton`.
- The `right` image is `np.fliplr` of the `left` image, an exact pixel mirror made in Python (A-24), not drawn again.
- It returns 36 `Frame(frame_name(key, "idle", dir, 0), draw.to_image(img))`.

## Acceptance criteria
- **AC1** Exactly the 36 contract frames exist, each 32×32: `actor/<key>/idle/<dir>/0` for the keys `human, elf, dwarf, orc, foxfolk, bearfolk, rabbitfolk, birdfolk, lizardfolk` and the dirs `down, left, right, up`. Proven by `test_actor_frames_match_contract` and by the atlas-JSON check in **Verification commands**.

- **AC3** Clipping fails the build loudly. Every shipped frame passes the cell check (the build succeeds), and an oversized species raises `ValueError` naming the species. Proven by `test_oversized_species_fails_cell_check` and a green `npm run build`.
- **AC4** Deterministic. Two builds produce byte-identical `core.png` and `core.json`. Proven by the `cmp` commands and the existing `test_build_is_byte_identical`.
- **AC5** The actor palette is exactly the locked set and validated. Proven by the palette one-liner in **Verification commands** (exits 0). `build.py` already validates every palette through `load_all()`.
- **AC6** The design is data-driven and draws colours only from the palette. Proven by the greps in **Verification commands**:
  - no species key appears in `gen/actor.py` or `lib/skeleton.py`;
  - no hex literal appears in `gen/actor.py`, `lib/species.py` or `lib/skeleton.py`;
  - no `rng`, `random` or `hash(` appears in the three new modules.
- **AC7** It looks right. The worker writes the contact sheet (command below), views it, and reports one line per species on how it reads: are the silhouettes distinct, do the 4 directions make sense, are clothes visible. The critic regenerates and views the same sheet.
- **AC8** Typecheck, lint, tests and build are clean. Proven by `npm run check && npm test && npm run build` → exit 0.
- **AC9** CLAUDE.md lists the three new contracts. Proven by the CLAUDE.md grep in **Verification commands**, which must print 3.

## Tests
`tools/art/tests/test_actor.py`. Show that each test fails against a deliberately broken version, then revert.

- **`test_actor_frames_match_contract`**
  - What it checks: it runs `actor.generate(Context(1, "actor"))`. The set of frame names must equal the 36 names built from a **literal** list of the 9 contract keys and 4 dirs in the test, not from `SPECIES`. Every image must be 32×32 RGBA.
  - What it guards: a renamed or dropped species key or direction, which TEC-022 would only discover at runtime as a missing frame.
- **`test_right_mirrors_left_with_sides_swapped`**
  - What it checks:
    - For every species, the right image equals `np.fliplr` of the left image.
    - `base_skeleton(sp, "right")["hand_r"] == Point(31 - left["hand_l"].x, left["hand_l"].y)`, and `right.near == "r"`.
    - In `down`, `hand_r.x < hand_l.x`. In `up`, `hand_r.x > hand_l.x`.
  - What it guards: the l/r handedness convention that ART-009 needs for main-hand weapons, and A-24's mirroring.
- **`test_oversized_species_fails_cell_check`**
  - What it checks: `draw_body` on `dataclasses.replace(<human row>, head_h=16)` with its `base_skeleton(..., "down")` raises `ValueError` whose message contains `human`. With that change every joint is still inside the cell, but the head top is clipped.
  - What it guards: silent clipping of a species that has grown too big.

Determinism gets no new test. The existing `test_build_is_byte_identical` builds in two separate processes and therefore also catches `PYTHONHASHSEED`- or set-order-dependent output. Looks are checked by the contact sheet and the M1 E2E, not by tests.
