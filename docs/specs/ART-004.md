## Locked design

### Concepts (dual grid)
- A **render cell** is a 16×16 square whose 4 corners sit on the centres of 4 world tiles. Render cell `(rx, ry)` has corners TL = tile `(rx, ry)`, TR = `(rx+1, ry)`, BL = `(rx, ry+1)`, BR = `(rx+1, ry+1)`. It is drawn with its top-left pixel at world px `(rx*16 + 8, ry*16 + 8)`. WLD-003 owns the drawing. This task only documents the convention in `tile-frames.ts`.
- **Corner mask bits:** TL = 1, TR = 2, BL = 4, BR = 8. Masks run 1..15. In a frame, pixel `(x, y)` with x, y in 0..15 is closest to TL at (0,0) and to BR at (15,15).
- **Terrain precedence**, lowest to highest: `very_deep_water < deep_water < shallow_water < sand < dirt < grass < stone < cliff`. Higher terrains draw over lower ones. Reasons: land edges are drawn over water, so shores get the ragged shape. Sand sits between water and land, so it forms beaches. Grass encroaches on dirt paths. Stone outcrops sit on grass. Cliff is the highest because its 3/4 face is drawn over whatever lies below it.
- **Layering rule.** For a render cell, take the distinct terrains among its 4 corners and sort them by precedence, lowest first. For each terrain T, emit one frame with `mask = Σ bit(corner)` over the corners whose precedence is **≥ T**. The lowest present terrain therefore always has mask 15 and is an opaque base. Each higher layer has mask 1..14.
  - Consequences: the lowest-precedence terrain (`very_deep_water`) only ever needs mask 15. Every other terrain needs masks 1..15, and all of those are reachable.
- **Variants:** `FULL_VARIANTS = 3` for mask 15 and `EDGE_VARIANTS = 2` for masks 1..14. Change them only together with the fixture.
- **Biome palette boundary:** a render cell uses the palette of the biome of its **TL corner tile**. Palette boundaries are therefore hard and follow render-cell edges, a staircase half a tile off the biome boundary. This is accepted for M1. Blending is a later polish.

### Frame names (contract)
`tile/<palette>/<terrain>/<mask>/<variant>`
- `palette`, in `Biome` value order: `meadow` (Grassland 0), `forest` (Forest 1), `river` (River 2), `mountain` (Mountain 3), `ocean` (Ocean 4).
- `terrain`, in `Tile` value order: `grass, dirt, sand, stone, cliff, shallow_water, deep_water, very_deep_water` (the snake_case of the enum names).
- `mask`: a decimal integer 1..15, with no padding. `variant`: a 0-based decimal integer.
- Example: `tile/meadow/grass/15/0`, `tile/ocean/sand/5/1`.
- Frame count: 5 palettes × (1 × 3 + 7 × (14 × 2 + 3)) = **1100 frames** of 16×16.

### `client/src/render/tile-frames.ts` (new)
Imports only `Tile`/`TileValue` from `@overgrown/sim/world/tile` and `Biome`/`BiomeValue` from `@overgrown/sim/world/biome`. It must not import `chunk-gen`, `noise`, `rng`, pixi or anything else.
```ts
/** Frame-name terrain key per Tile. Adding a Tile without a key fails typecheck. */
export const TERRAIN_KEYS: Record<TileValue, string>;      // grass, dirt, sand, stone, cliff, shallow_water, deep_water, very_deep_water
/** Draw order: 0 = lowest (very_deep_water) … 7 = highest (cliff). */
export const TERRAIN_RANK: Record<TileValue, number>;
/** Palette (frame-name key) per Biome. */
export const BIOME_PALETTES: Record<BiomeValue, string>;   // meadow, forest, river, mountain, ocean
export const FULL_MASK = 15;
export const FULL_VARIANTS = 3;
export const EDGE_VARIANTS = 2;

export function tileFrameName(biome: BiomeValue, terrain: TileValue, mask: number, variant: number): string;
//   `tile/${BIOME_PALETTES[biome]}/${TERRAIN_KEYS[terrain]}/${mask}/${variant}`; the only place the format is spelled out in TS

/**
 * Frames to draw, bottom first, for render cell (rx, ry). Its corners are tiles tl=(rx,ry), tr=(rx+1,ry), bl=(rx,ry+1),
 * br=(rx+1,ry+1); it is drawn at world px (rx*16+8, ry*16+8); its palette is the biome of the TL tile.
 * Returns 1–4 names; the first always has mask 15.
 */
export function tileFrames(tl: TileValue, tr: TileValue, bl: TileValue, br: TileValue, biome: BiomeValue, rx: number, ry: number): string[];
```
Algorithm (locked):
```
validate: each corner is an own key of TERRAIN_KEYS and biome an own key of BIOME_PALETTES, and rx, ry satisfy Number.isInteger.
          Otherwise throw RangeError naming the argument and the value, e.g. "br must be a Tile value, got 9".
          (Chunk data arrives as Uint8Array numbers; a corrupt byte must be an error, not a missing texture.)
corners = [tl, tr, bl, br]                       // index i ↔ bit 1 << i
for each distinct T in corners, ascending TERRAIN_RANK:
  mask = OR of (1 << i) for every i with TERRAIN_RANK[corners[i]] >= TERRAIN_RANK[T]
  n = mask === FULL_MASK ? FULL_VARIANTS : EDGE_VARIANTS
  push tileFrameName(biome, T, mask, cellHash(rx, ry, T) % n)

cellHash(rx, ry, t):                             // module-private; stable, so a re-baked chunk looks identical
  let h = Math.imul(rx, 0x9e3779b1) ^ Math.imul(ry, 0x85ebca77) ^ Math.imul(t + 1, 0xc2b2ae3d);
  h ^= h >>> 16; h = Math.imul(h, 0x7feb352d); h ^= h >>> 15; h = Math.imul(h, 0x846ca68b); h ^= h >>> 16;
  return h >>> 0;
```
Variant placement does not depend on the world seed. Art is the same for every world.

### `tools/art/gen/tiles.py` (new generator)
```python
NAME = "tile"
ATLAS = "core"
SIZE = 16
PALETTES = ("meadow", "forest", "river", "mountain", "ocean")
PRECEDENCE = ("very_deep_water", "deep_water", "shallow_water", "sand", "dirt", "grass", "stone", "cliff")
WATER = frozenset({"shallow_water", "deep_water", "very_deep_water"})
TILE_RAMPS = (*PRECEDENCE, "detail")      # ramps every biome palette must have
FULL_MASK, FULL_VARIANTS, EDGE_VARIANTS = 15, 3, 2
EDGE_NOISE = 0.3                          # tunable
FACE_H = 4                                # cliff face height in px, tunable

def frame_name(palette: str, terrain: str, mask: int, variant: int) -> str   # the only place the format is spelled out in Python
def masks(terrain: str) -> tuple[int, ...]     # (15,) for PRECEDENCE[0], else 1..15
def variants(mask: int) -> int
def coverage(mask: int, rng: Rng) -> np.ndarray   # bool (16, 16), formula below
def draw_tile(ctx: Context, palette: str, terrain: str, mask: int, variant: int) -> np.ndarray   # (16,16,4) uint8
def generate(ctx: Context) -> list[Frame]      # loops PALETTES × PRECEDENCE × masks × variants in that tuple order
```
`gen/__init__.py`: `from gen import debug, tiles` and append `tiles` to `GENERATORS`. ART-005 appends `actor` to the same two lines concurrently. Whoever rebases second keeps both, giving `GENERATORS = [debug, actor, tiles]` in any order. That is the only file the two tasks share in `tools/art/`.

**Coverage (locked formula; the seam test depends on it).** For a mask with corner bits `a_tl, a_tr, a_bl, a_br` ∈ {0, 1}, and pixel indices x, y in 0..15:
```
u = x / 15,  v = y / 15                                   # exactly 0 on column/row 0 and 1 on column/row 15
bil = a_tl(1-u)(1-v) + a_tr·u(1-v) + a_bl(1-u)v + a_br·uv
lattice: 5×5 floats, rng.next_float()*2-1, drawn row-major (row j = 0..4 outer, column i = 0..4 inner)
         from rng = ctx.rng("edge", terrain, mask, variant)     # shape independent of palette
n(x, y) = bilinear sample of lattice at gx = u*4, gy = v*4 (cell index min(floor(g), 3))
w(x, y) = min(x, 15-x, y, 15-y, 2) / 2                     # 0 on the outer ring, 1 from 2 px in
covered = bil + EDGE_NOISE * w * n > 0.5
```
On the outer ring, coverage depends only on the two corners of that edge: rows 0..7 or columns 0..7 belong to the first corner and 8..15 to the second. Adjacent cells share corners, so every boundary meets the neighbouring frame exactly. Do not add noise, rims or outlines that put opaque pixels on the ring outside this rule.

**Drawing rules.**
- Mask 15: a fully opaque textured tile.
- Masks 1..14: the texture, opaque exactly where `covered`, alpha 0 elsewhere. The cliff face below is the only addition.
- **Rim:** covered pixels that have an uncovered 4-neighbour **inside the frame** get a rim colour from the terrain's own ramp. Out-of-frame neighbours count as covered. Starting style: land uses `ramp[0]` and water uses `ramp[-1]`, a light shelf or foam line. Rims never add pixels outside `covered`.
- **Texture** is drawn with `ctx.rng(palette, terrain, mask, variant)`. Any feature larger than 1 px, such as a blade, pebble, glint or flower, lies fully inside rows and columns 1..14, so nothing is cut at a frame border. Per-pixel speckle may touch the border. `detail` specks (flowers, leaf litter, pebbles, shells) appear sparsely on `grass` and `dirt` only.
- **Cliff (OQ-018, 3/4 rock face):**
  - The top surface is the coverage, textured in the upper shades of `cliff`.
  - The **face** is every in-frame pixel that is not covered and has a covered pixel 1..`FACE_H` rows directly above it, with all face pixels on row 15 removed.
  - Paint the face in the two darkest `cliff` shades with vertical striations, and make its lowest pixel in each column `cliff[0]` (a shadow line).
  - Result: a south-facing cliff edge shows a face 4 px tall over the tile below, and the face is continuous across cells because the ring rule fixes the edge at row 7 of columns 0 and 15.
- **Colours** come only from `ctx.palette(palette).ramp(<terrain>)` and `.ramp("detail")`. There are no hex literals in `gen/tiles.py`, no `random`, no `hash()` and no iteration over sets or dicts whose order isn't fixed.
- **Prototype check:** a reference prototype of exactly this design generates 1100 frames in about 0.5 s and passes both Python tests below. It is in the orchestrator's scratchpad (`a4p/`) and is not for the worker.

`client/src/render/tile-frames.test.ts` (vitest; imports `../../../contracts/tile-frames.json`, as `rng.test.ts` does)

   - What it checks:

     - The Set equals the fixture-derived expected set (1100 names).
     - Each call returns 1–4 names, and the first name's mask is 15.
     - Pass an explicit timeout of 30 000 ms (about 1.3 M calls).
   - What it guards: a lookup that requests a frame the pipeline never draws (a hole in the ground), or a rule change that leaves frames unreachable. To show it can fail, change `>=` to `>` in the mask rule.
3. **Validation.**
   - What it checks: `tileFrames(0, 0, 0, 8 as TileValue, 0, 0, 0)`, biome `5 as BiomeValue`, and `rx = 0.5` each throw a RangeError whose message names `br`, `biome` and `rx` respectively.

     - row 0: TL on columns 0..7, TR on columns 8..15;
     - row 15: the same with BL and BR.
     - Cliff only: on columns 0 and 15, when the top corner is set and the bottom corner is not, rows 8..7+`FACE_H` are opaque too.
   - What it guards: visible seams along every terrain boundary in game, which a contact sheet of isolated frames would not show. To show it can fail, use `w = min(x, 15-x, y, 15-y, 2)/2 + 0.5`.

import json, math, sys
from pathlib import Path
from PIL import Image
out, dest = Path(sys.argv[1]), sys.argv[2]
fx = json.loads(Path("contracts/tile-frames.json").read_text())
atlas = Image.open(out / "core.png")
frames = json.loads((out / "core.json").read_text())["frames"]
rank = {t: i for i, t in enumerate(fx["precedence"])}
W, H, S = 32, 18, 2
def terrain(x, y):
    e = x / W + 0.08 * math.sin(y * 0.7) + 0.05 * math.sin(x * 1.3 + y)
    t = ("very_deep_water" if e < .12 else "deep_water" if e < .2 else "shallow_water" if e < .3
         else "sand" if e < .38 else "grass" if e < .8 else "stone")
    if t == "grass" and abs(y - 9 - 2 * math.sin(x * .4)) < 1.2: t = "dirt"
    if 22 <= x <= 27 and 2 <= y <= 6: t = "cliff"
    if 24 <= x <= 30 and 11 <= y <= 15: t = "cliff"
    if 16 <= x <= 18 and 13 <= y <= 15: t = "shallow_water"
    return t
grid = [[terrain(x, y) for x in range(W)] for y in range(H)]
def panel(palette_of):
    img = Image.new("RGBA", ((W - 1) * 16, (H - 1) * 16))
    for ry in range(H - 1):
        for rx in range(W - 1):
            c = [grid[ry][rx], grid[ry][rx + 1], grid[ry + 1][rx], grid[ry + 1][rx + 1]]

    return img.resize((img.width * S, img.height * S), Image.NEAREST)
panels = [panel(lambda rx, p=p: p) for p in fx["palettes"]]
panels.append(panel(lambda rx: "meadow" if rx < 16 else "forest"))
pw, ph, pad = panels[0].width, panels[0].height, 8

for i, p in enumerate(panels):
