# TEC-001: Pixi client boots a blank scene, deployed to GitHub Pages

## Desired result
Opening the built client shows a full-viewport PixiJS canvas (pixel-art settings, phone-friendly, no scrolling), with no console errors. Every push to main deploys `client/dist` to GitHub Pages.

## Locked design
- Add dependency `pixi.js` (current stable v8) to `@overgrown/client`. Nothing else.
- `client/src/main.ts`:
  - `const app = new Application(); await app.init({ resizeTo: window, background: "#1d2b22", antialias: false, resolution: window.devicePixelRatio || 1, autoDensity: true })`, and `TextureStyle.defaultOptions.scaleMode = "nearest"` set before any texture exists.
  - Append `app.canvas` to `#app`.
  - A small debug `Text` in the top-left corner: `overgrown · sim v<SIM_VERSION>` (import from `@overgrown/sim/version`), white, ~12px, so the sim link stays visible.
  - If `app.init` throws (no WebGL), replace `#app` content with a readable DOM message: "overgrown couldn't start the renderer: <error message>". Don't swallow the error; also `console.error` it.
- `client/index.html`: html/body/#app at 100% width and height, margin 0, overflow hidden, background #1d2b22, `touch-action: none`, `user-select: none`; `<link rel="icon" href="data:,">` so there's no favicon 404; `<meta name="theme-color" content="#1d2b22">`.
- `.github/workflows/deploy.yml`: on push to main and workflow_dispatch. Job `build`: checkout, setup-node 22 (npm cache), setup-python 3.13, `pip install -r tools/art/requirements.txt`, `npm ci`, `npm run build`, `actions/upload-pages-artifact` with path `client/dist`. Job `deploy` (needs build): `actions/deploy-pages`, `environment: github-pages` with the page URL output. Permissions: contents read, pages write, id-token write. `concurrency: { group: pages, cancel-in-progress: true }`. Use the current major versions of those actions.

Note: GitHub Pages isn't enabled on the repo yet (Lucid has to switch Settings → Pages → Source to "GitHub Actions"; the API is blocked from here). So the deploy can't be verified live in this task; verify the workflow file and the local build instead.

## Acceptance criteria
- AC1 Build is green — proven by: `npm run check && npm test && npm run build` → exit 0.
- AC2 The built page boots Pixi with no errors — proven by: `npm -w @overgrown/client run preview -- --port 4173 &` then `node /home/claude/pwtools/check.mjs http://localhost:4173/ /tmp/tec001.png` → `"canvas": true`, `"errors": []`, exit 0; the screenshot shows the dark green background and the debug text.
- AC3 Renderer failure is visible, not silent — proven by: temporarily making init throw (e.g. `throw new Error("test")` before init), rebuilding and re-running check.mjs → page text contains "couldn't start the renderer: test"; revert.
- AC4 Deploy workflow is well-formed — proven by: `python3 -c "import yaml,sys;yaml.safe_load(open('.github/workflows/deploy.yml'))"` (install pyyaml in a throwaway way if needed; don't add it to requirements) → no error; it references `client/dist` and has the three permissions.
