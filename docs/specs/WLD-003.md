# WLD-003: Chunk streaming, the chunk cache and the baked ground layer

GDD: docs/gdd/02-world.md — "**WLD-003** `[proto]` Chunk streaming: load and unload around players; cache generated chunks. Spawn and zoom defaults in OQ-024."
Milestone: M1   Depends on: WLD-001 (merged #15), CHR-001 (merged #16), WLD-002, ART-004, CMB-001. All five must be merged before dispatch.
Model: opus — because this task creates the `chunk`/`unchunk` protocol, the `tileAt` contract that WLD-004 collision builds on, a per-tick generation budget and the dual-grid edge re-bake rule; bugs in any of them are silent (stale seams, detached buffers, unbounded memory) until a long walk.
Branch: wld-003-chunk-streaming

## Desired result
The sim keeps generated chunks in a cache, streams the 5×5 chunks around every character driven by a host input channel to the host (at most 2 new generations per tick, nearest first), unloads chunks more than 3 chunks away, and answers `tileAt(tx, ty)` for any tile by generating synchronously if needed. The client bakes each received chunk's dual-grid ground once into a 512×512 texture, so the page shows real biome ground under the character, and a 10-chunk sprint does not stall. The same seed and the same inputs give identical snapshots and identical chunk messages.

## Locked design

### Numbers this design is built on
- Generation cost, measured on WLD-002's branch in Node 22 (this container, `generateChunk(42, …)`, 200 chunks after warm-up): **median 1.6 ms, mean 2.0 ms, p95 3.9 ms, max 6.5 ms** per chunk. Copying one chunk's two 1 KiB layers: about 1.4 µs.
- Tick: 50 ms (20 Hz). Fastest movement: sprint 128 px/s = 6.4 px/tick (CMB-001), so a chunk boundary (512 px) is crossed at most once per 80 ticks, and one crossing needs at most 9 new chunks (diagonal) or 5 (straight).
- Zoom (OQ-024, CMB-001 `integerScale`): the short axis shows 16 to < 32 tiles. The tallest common screen (390×844, aspect 2.16) therefore shows < 70 tiles on the long axis, i.e. < 35 tiles (560 px, 1.1 chunks) from the camera to the screen edge. From anywhere inside its chunk, the camera never sees a chunk more than 2 chunks away (Chebyshev). Load radius 2 covers every visible chunk up to aspect ≈ 2.2; a 5×5 hot zone is 160 tiles across, 2.3–5 screens (02-world "≈ 2 screens", conflict 15 resolved).

### Constants (`sim/src/world/chunk-store.ts`; all tunable)
```ts
/** Chebyshev radius, in chunks, around each anchor's chunk that is loaded and sent to the host. */
export const LOAD_RADIUS = 2;
/** Loaded chunks farther than this (Chebyshev, chunks) from every anchor's chunk are unloaded. > LOAD_RADIUS (hysteresis). */
export const UNLOAD_RADIUS = 3;
/** Most chunks stream() generates per tick. Cache hits and tileAt() generation don't count. */
export const GEN_PER_TICK = 2;
/** LRU capacity for unloaded chunks kept for a quick return. Loaded chunks are never evicted and don't count. */
export const RECENT_CHUNKS = 64;
```
Why these values (for the critic; do not re-decide):
- **GEN_PER_TICK = 2:** 2 × p95 3.9 ms ≈ 8 ms = 16 % of the 50 ms tick on desktop; on a 4×-slower phone CPU (the M0 emulation profile) about 16 ms mean and 31 ms p95, still inside the tick with room for the rest of the sim. Steady state needs at most 9 chunks per 80 ticks, so 2/tick finishes a crossing's prefetch in ≤ 5 ticks (≤ 32 px of sprint). Startup loads all 25 chunks in 13 ticks (0.65 s), and the visible ones come first (priority below). 1/tick would double startup; 4/tick would put a phone tick at ~60 ms p95.
- **RECENT_CHUNKS = 64:** 128 KiB of RAM. It covers turning back after walking up to ~12 chunks in a straight line (5 chunks unload per crossing) without regenerating anything. The cap exists because the cache is not a save (01-tech "Persistence"): a long walk must not grow memory without bound.
- **Loaded chunks are pinned**, not counted in the LRU, so several anchors (later TEC-011, up to 10 players) can never thrash a shared cap.

### Protocol (`sim/src/protocol.ts`)
Add, and widen `SimToHost`:
```ts
/** A loaded chunk, sent once per load (M1 contract "Chunk transport"). The host owns these arrays: they are copies, and the worker transfers their buffers. */
export interface ChunkMessage {
  type: "chunk";
  cx: number;
  cy: number;
  /** TileValue per tile, local index ly * CHUNK_TILES + lx, length CHUNK_TILES². */
  tiles: Uint8Array<ArrayBuffer>;
  /** BiomeValue per tile, same indexing. */
  biomes: Uint8Array<ArrayBuffer>;
}
/** The host may drop chunk (cx, cy); the sim sends a new ChunkMessage if it loads it again. */
export interface UnchunkMessage { type: "unchunk"; cx: number; cy: number }
export type ChunkStreamMessage = ChunkMessage | UnchunkMessage;
export type SimToHost = { type: "snapshot"; snapshot: Snapshot } | ChunkStreamMessage | { type: "error"; message: string };
/** The transfer list for postMessage: both layers, so nothing is copied twice. */
export function chunkBuffers(m: ChunkMessage): ArrayBuffer[]; // [m.tiles.buffer, m.biomes.buffer]
```
**Ownership (locked):** the sim's cache owns the `ChunkData` arrays from `generateChunk` and never posts them. Each `ChunkMessage` carries `tiles.slice()` and `biomes.slice()`. Reason: a transferred buffer is detached in the sender (length 0), so posting cache arrays would break `tileAt` and every later reload of that chunk. The copy costs ~1.4 µs per chunk.

### Chunk store (`sim/src/world/chunk-store.ts`, new)
Inside the WLD-001 ESLint worldgen block: only `Math.floor/min/max/abs/imul`, `+ - * /`; no `Date`, no `**`. Imports: `../constants`, `../protocol` (types), `./chunk-gen`, `./tile`.
```ts
export interface ChunkCoord { cx: number; cy: number }
export interface AnchorPos { x: number; y: number } // world px (a character's Position)
export interface StreamPlan { unload: ChunkCoord[]; load: ChunkCoord[] }
export type GenerateChunk = (seed: number, cx: number, cy: number) => ChunkData;

/** Chunk coordinate of a world px coordinate: Math.floor(Math.floor(px / TILE_PX) / CHUNK_TILES) (M1 contract). */
export function chunkOf(px: number): number;

/**
 * Pure. unload: every chunk in `loaded` whose Chebyshev distance to every anchor's chunk exceeds UNLOAD_RADIUS,
 * in `loaded` iteration order. load: every chunk within LOAD_RADIUS of some anchor's chunk that is not in `loaded`,
 * sorted by (d², cy, cx) ascending, where d² is the smallest squared distance from an anchor position to the chunk
 * centre (cx * CHUNK_PX + CHUNK_PX / 2, cy * CHUNK_PX + CHUNK_PX / 2), CHUNK_PX = TILE_PX * CHUNK_TILES.
 * RangeError naming the anchor index if an anchor coordinate is not finite. No anchors → unload everything, load nothing.
 */
export function planStream(anchors: readonly AnchorPos[], loaded: Iterable<ChunkCoord>): StreamPlan;

export interface ChunkStore {
  /** The tile at world tile (tx, ty). Generates the chunk synchronously if it isn't cached, so it is never undefined.
   *  RangeError naming tx or ty unless it is an integer; generateChunk's RangeError for chunks outside its range. */
  tileAt(tx: number, ty: number): TileValue;
  /** One tick of streaming for these anchors: queues unchunk then chunk messages (algorithm below). */
  stream(anchors: readonly AnchorPos[]): void;
  /** Returns the messages queued since the last call, in order, and clears the queue. */
  drain(): ChunkStreamMessage[];
  /** Sizes, for tests and a later perf HUD (TEC-015). */
  counts(): { loaded: number; recent: number };
}
/** `generate` exists so tests can count generations; production passes nothing. */
export function createChunkStore(seed: number, generate: GenerateChunk = generateChunk): ChunkStore;
```
State: `loaded: Map<string, ChunkData>` and `recent: Map<string, ChunkData>` (insertion order = LRU order, oldest first), keyed `` `${cx},${cy}` ``; `out: ChunkStreamMessage[]`.

Algorithm (locked):
```
remember(key, d):  recent.delete(key); recent.set(key, d); while recent.size > RECENT_CHUNKS: delete recent's first key

lookup(cx, cy):    key → loaded.get(key)
                   ?? (recent hit: delete + set to mark it most recent, return it)
                   ?? (d = generate(seed, cx, cy); remember(key, d); return d)

tileAt(tx, ty):    validate; cx = Math.floor(tx / CHUNK_TILES); lx = tx - cx * CHUNK_TILES (same for y)
                   return lookup(cx, cy).tiles[ly * CHUNK_TILES + lx]

stream(anchors):
  plan = planStream(anchors, loaded.values())
  for c of plan.unload:  d = loaded.get(key); loaded.delete(key); remember(key, d); out.push({ type: "unchunk", cx, cy })
  generated = 0
  for c of plan.load:
    if recent has key:                 d = recent.get(key); recent.delete(key)      // free
    else if generated < GEN_PER_TICK:  d = generate(seed, cx, cy); generated += 1
    else continue                      // later cache hits in the list still load this tick
    loaded.set(key, d); out.push({ type: "chunk", cx, cy, tiles: d.tiles.slice(), biomes: d.biomes.slice() })
```
Consequences (locked): on-demand `tileAt` generation ignores the budget (collision is never undefined; A-15) and feeds `recent`, so a chunk that collision touched first streams later for free. Unloading never discards data; it only moves the chunk into the LRU.

### Worker (`client/src/sim-worker.ts`)
In the loop, after the steps and **before** the snapshot: `for (const m of sim.drainChunkMessages()) scope.postMessage(m, m.type === "chunk" ? chunkBuffers(m) : [])`. Then the snapshot, as now. The renderer therefore has a tick's chunks before its snapshot.

### Ground layer (`client/src/render/chunk-layer.ts`, new)
```ts
/** Wall-clock ms per frame spent baking (at least one bake per frame when any is queued). Tunable. */
export const BAKE_BUDGET_MS = 4;
export class ChunkLayer {
  /** Adds its own layer to `parent` (construct it before SnapshotView so ground draws under characters). */
  constructor(parent: Container, sheet: Spritesheet, renderer: Renderer);
  /** Holds the chunk and queues bakes. Error if (cx, cy) is already held, or a layer's length isn't CHUNK_TILES². */
  add(msg: ChunkMessage): void;
  /** Drops the chunk: destroys its sprite and RenderTexture, removes it from the bake queue. Error if not held. */
  remove(cx: number, cy: number): void;
  /** Once per frame: bakes queued chunks oldest first until BAKE_BUDGET_MS has elapsed. */
  update(): void;
}
```
**Rendering technique (A-16, locked): one 512×512 RenderTexture per held chunk**, `resolution: 1`, nearest sampling, shown by one `Sprite` at world px `(cx * 512 + 8, cy * 512 + 8)` (the dual grid is offset by half a tile, ART-004).
- Why baked (M0 fill-rate notes): M0's software-GL fps fell 60 → 30 → 15 as pixel count rose ×4 and ×9, i.e. the renderer is fill-bound. A baked chunk draws every ground pixel exactly once with one quad. Per-tile sprites would draw ~1.3–2 alpha-blended layers per pixel (dual-grid transitions) plus 25–40 k quads per frame of batching on the main thread. Baking is the minimum possible fill and constant per-frame CPU.
- Cost (accepted for M1): 1 MiB of GPU memory per held chunk: 25 MiB at rest, up to 49 MiB inside the hysteresis band (7×7). There is no separate, smaller render radius; TEC-020 and the M1 E2E measure on phones.

**Bake (locked):** for chunk (cx, cy), with `tx0 = cx * 32`, `ty0 = cy * 32`, for each `ly`, `lx` in 0..31 (render cell `rx = tx0 + lx`, `ry = ty0 + ly`):
```
corner(tx, ty) = tile of the held chunk containing (tx, ty);
                 if that chunk isn't held: this chunk's own tile at (min(tx - tx0, 31), min(ty - ty0, 31))   // stand-in (clamp)
names = tileFrames(corner(rx, ry), corner(rx+1, ry), corner(rx, ry+1), corner(rx+1, ry+1), biomes[ly*32 + lx], rx, ry)
each name → a Sprite of sheet.textures[name] at local (lx * 16, ly * 16), in order (bottom first)
```
Render the temporary container into the chunk's RenderTexture (`renderer.render({ container, target, clear: true })`; create the texture on the first bake, reuse it on re-bakes), then destroy the temporary sprites (never the atlas textures). A missing atlas frame is an Error naming the frame. Only TR, BL and BR can fall outside the chunk (east, south, south-east neighbours). The palette is always the chunk's own (TL corner, ART-004).

**Edges and re-bakes (locked):** `add(msg)` queues (cx, cy) and, if held, its west (cx−1, cy), north (cx, cy−1) and north-west (cx−1, cy−1) neighbours: exactly the chunks whose east/south edge cells read the new chunk. The queue is an insertion-ordered set (a chunk already queued keeps its place). Baking reads whatever is held at bake time. `remove` re-bakes nothing: chunk data never changes, so a neighbour's edge stays correct. Result: a stand-in edge is visible only while a neighbour is still in flight, at the far edge of the 5×5 zone except for the first ticks after load.

**Main thread (`client/src/main.ts`):** construct `const ground = new ChunkLayer(world, sheet, app.renderer)` before `new SnapshotView(world, sheet)`. The worker `message` handler becomes an exhaustive `switch` (`snapshot` as now, `chunk` → `ground.add`, `unchunk` → `ground.remove`, `error` → showFatal, `default` → a `never` check), wrapped in try/catch: on a throw, stop the ticker, terminate the worker and `showFatal("overgrown couldn't draw the world", error)`. In the ticker, call `ground.update()` after the camera lines and before `view.update(frame)`. `background: "#1d2b22"` stays: it is the clear colour shown before the first bake, not a placeholder backdrop (CHR-001 removed the mover backdrop).

// WLD-003 scripted walk. Run from the repo root: node --input-type=module < /tmp/wld003-walk.mjs
import { chromium } from "playwright-core";

const URL = "http://localhost:4198/?seed=1";
const TARGET = 10; // chunks, Chebyshev, diagonal = 9 new chunks per crossing (worst case)
const errors = [];

// Runs in the page before app code: counts chunk traffic, snapshot gaps and frame gaps while walking.
function instrument() {
  const w = (window.__w = { you: null, walking: false, chunks: 0, unchunks: 0, held: 0, maxHeld: 0, badChunks: 0,
    firstChunkAt: -1, lastSnapAt: -1, maxSnapGap: 0, frames: [] });
  const Base = window.Worker;
  window.Worker = class extends Base {
    constructor(...args) {
      super(...args);
      this.addEventListener("message", (e) => {
        const m = e.data;
        const now = performance.now();
        if (m.type === "chunk") {
          w.chunks += 1; w.held += 1; w.maxHeld = Math.max(w.maxHeld, w.held);
          if (w.firstChunkAt < 0) w.firstChunkAt = now;
          if (m.tiles.length !== 1024 || m.biomes.length !== 1024) w.badChunks += 1;
        } else if (m.type === "unchunk") {
          w.unchunks += 1; w.held -= 1;
        } else if (m.type === "snapshot") {
          if (w.walking && w.lastSnapAt >= 0) w.maxSnapGap = Math.max(w.maxSnapGap, now - w.lastSnapAt);
          w.lastSnapAt = now;
          const s = m.snapshot;
          const i = s.ids.indexOf(s.you);
          if (i >= 0) w.you = { tick: s.tick, x: s.x[i], y: s.y[i] };
        }
      });
    }
  };
  let last = -1;
  const loop = (t) => {
    if (w.walking && last >= 0) w.frames.push(t - last);
    last = t;
    requestAnimationFrame(loop);
  };
  requestAnimationFrame(loop);
}

const browser = await chromium.launch();
let r;
try {
  const page = await browser.newPage({ viewport: { width: 1280, height: 720 } });
  page.on("pageerror", (e) => errors.push(`pageerror: ${e.message}`));
  page.on("console", (m) => { if (m.type() === "error") errors.push(`console: ${m.text()}`); });
  await page.addInitScript(instrument);
  await page.goto(URL);
  await page.waitForFunction(() => window.__w.you !== null && window.__w.chunks >= 25, null, { timeout: 10000 });
  await page.waitForTimeout(1000);
  await page.evaluate(() => { window.__w.walking = true; });
  for (const k of ["ShiftLeft", "KeyD", "KeyS"]) await page.keyboard.down(k);
  await page.waitForFunction(
    (t) => Math.floor(window.__w.you.x / 512) >= t && Math.floor(window.__w.you.y / 512) >= t,
    TARGET, { timeout: 120000, polling: 250 });
  await page.evaluate(() => { window.__w.walking = false; });
  for (const k of ["KeyS", "KeyD", "ShiftLeft"]) await page.keyboard.up(k);
  await page.waitForTimeout(1500);
  await page.screenshot({ path: "/tmp/wld003-walk.png" });
  r = await page.evaluate(() => {
    const w = window.__w;
    const f = [...w.frames].sort((a, b) => a - b);
    const q = (p) => f[Math.min(f.length - 1, Math.floor(p * f.length))];
    return { you: w.you, chunks: w.chunks, unchunks: w.unchunks, held: w.held, maxHeld: w.maxHeld, badChunks: w.badChunks,
      firstChunkAt: Math.round(w.firstChunkAt), maxSnapGap: Math.round(w.maxSnapGap), frames: f.length,
      p50: q(0.5), p95: q(0.95), max: f.at(-1) };
  });
} finally {
  await browser.close();
}

const checks = {
  reached: Math.floor(r.you.x / 512) >= TARGET && Math.floor(r.you.y / 512) >= TARGET,
  noFrameStall: r.max <= 100,
  noSimStall: r.maxSnapGap <= 150,
  heldBounded: r.maxHeld <= 49 && r.held >= 25,
  unloaded: r.unchunks > 0,
  wellFormed: r.badChunks === 0,
  noErrors: errors.length === 0,
};
console.log(JSON.stringify({ checks, results: r, errors }, null, 2));
process.exitCode = Object.values(checks).every(Boolean) ? 0 : 1;
EOF
