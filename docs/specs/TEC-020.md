## Desired result
On a phone with devicePixelRatio 2.625 or 3, the canvas renders at a quarter of the device pixels and the browser upscales it by exactly ×2, so the game looks identical to the uncapped page (uniform art pixels, same zoom) at a fraction of the fill cost. Desktop at DPR ≤ 2 is unchanged. A DPR change at runtime (browser zoom, another screen) re-sizes the backing store without a reload. `?perf` shows an fps line a phone user can read off. Two committed scripts measure fps and first-frame time under a locked emulation recipe, and `docs/perf.md` records the numbers, says plainly that no real phone was measured, and tells Lucid how to measure one.

## Locked design

### Numbers this design is built on (measured while drafting, main a137bd1 + scratch patches, headless Chromium + SwiftShader)
- **The `Math.min(dpr, 2)` cap breaks pixel art.** At 412×915 CSS: DPR 2.625 → backing 824×1830, the compositor upscales ×1.3125 with nearest sampling, and the character's art pixels come out as a mix of 3- and 4-device-px blocks (figure 79×118 device px). At DPR 3 → mixed 4- and 5-px blocks, and the zoom changes (figure 90×135). CMB-001's rule "every texel on whole device pixels, no jitter at any DPR" no longer holds, and the unevenness crawls while the camera moves.
- **An integer-divisor cap keeps the image exact.** `resolution = dpr / ceil(dpr / 2)`: DPR 2.625 → 1.3125, backing 541×1201, upscaled exactly ×2; DPR 3 → 1.5, backing 618×1373. Screenshots are **identical in run-length structure to the uncapped page** (uniform 4×4 device-px art pixels, figure 80×120, the same zoom) with 25 % of the device pixels.
- fps, phone 390×844 at DPR 3, 4× CPU throttle, 5 s idle (pre-WLD-003, no ground): uncapped **22.8 fps** (backing 1170×2532), `Math.min(dpr, 2)` **43.9 fps** (780×1688), integer divisor **59.6 fps** (585×1266).
- `ResizeObserver` `device-pixel-content-box` is unsupported in Safari and iOS Safari (MDN browser-compat-data, `ResizeObserverEntry.devicePixelContentBoxSize`: safari `version_added: false`; Chrome 84, Firefox 108). The X in-app browser on iPhone is WebKit.
- A DPR change under CDP (`Emulation.setDeviceMetricsOverride`, 1 → 2.625) fires the `matchMedia("(resolution: 1dppx)")` change event; today Pixi then re-sizes with the stale resolution (backing 412×915 for a 1082-device-px-wide box).

### Render resolution (`client/src/render/resolution.ts`, new, pure: no DOM, no Pixi)
```ts
/** Starting cap for the render resolution (01-tech, OQ-023). Tunable; `?maxdpr=1..4` overrides it for measuring. */
export const MAX_RENDER_DPR = 2;
/**
 * The render resolution for a devicePixelRatio: dpr / k with k = Math.ceil(dpr / maxDpr), the smallest integer
 * that brings it to ≤ maxDpr. So the browser upscales the backing store by exactly k and every art pixel stays a
 * whole number of device pixels. dpr ≤ maxDpr → dpr unchanged.
 * RangeError unless dpr is finite and > 0 and maxDpr is an integer ≥ 1.
 */
export function renderResolution(dpr: number, maxDpr: number = MAX_RENDER_DPR): number;
```
Why not `Math.min(dpr, cap)` (the GDD's "e.g. ≤ 2" is met by both): see the numbers above. The camera needs no change: `integerScale` runs on `app.canvas.width/height` (the backing store), and backing × k = device px.

### `client/src/main.ts`
1. `function maxDprFromUrl(): number`, next to `seedFromUrl` and in the same style: `?maxdpr` missing → `MAX_RENDER_DPR`; `/^[1-4]$/` → that integer; anything else → `console.warn("overgrown: ignoring invalid ?maxdpr=<raw> (want an integer 1..4), using 2")` and `MAX_RENDER_DPR`. Read once at startup into `const maxDpr`.
2. `app.init({ …, resolution: renderResolution(window.devicePixelRatio || 1, maxDpr), … })`. Nothing else in the init options changes. Keep `pixelated`; it is now load-bearing (×k nearest upscale).
3. DPR changes, right after `root.appendChild(app.canvas)`:
   ```ts
   // Browser zoom or another screen changes devicePixelRatio; Pixi's resizeTo only tracks the CSS size.
   function watchDpr(onChange: () => void): void {
     const mq = window.matchMedia(`(resolution: ${window.devicePixelRatio || 1}dppx)`);
     mq.addEventListener("change", () => { watchDpr(onChange); onChange(); }, { once: true });
   }
   watchDpr(() => app.renderer.resize(window.innerWidth, window.innerHeight, renderResolution(window.devicePixelRatio || 1, maxDpr)));
   ```
   (`resizeTo: window` sizes from `innerWidth/innerHeight`; later window resizes keep the new resolution.)
4. **First-frame mark** (the startup metric; TEC-021 and the M1 E2E read it):
   - `export const FIRST_FRAME_MARK = "overgrown:first-frame";` in main.ts is not importable by scripts, so the name is a CLAUDE.md contract (below); define it as a module-level `const`.
   - `let chunksAdded = 0`, incremented right after every `ground.add(msg)` in the worker message handler.
   - At the end of the ticker callback's `try`, after `view.update(frame)`: if the mark isn't set yet and `chunksAdded > 0`, `performance.mark(FIRST_FRAME_MARK)` and remember that it is set (a boolean). Meaning: the first frame that draws a snapshot with at least one baked ground chunk (`ground.update()` bakes at least one queued chunk per frame, WLD-003). Pixi renders that frame right after the callback.
5. `?perf` (`new URLSearchParams(location.search).has("perf")`): construct `new PerfReadout(document.body)` and add a **separate** ticker callback `() => readout.frame(performance.now(), { dpr: window.devicePixelRatio || 1, resolution: app.renderer.resolution, width: app.canvas.width, height: app.canvas.height })`, so it counts frames before the first snapshot too. Without `?perf` nothing is created.

### `?perf` readout (`client/src/perf-readout.ts`, new)
```ts
/** `?perf`: one DOM line under the debug text, refreshed once per second. Debug only; TEC-015 grows it into the HUD. */
export class PerfReadout {
  /** Creates `<div id="perf">` and appends it to `parent`. */
  constructor(parent: HTMLElement);
  /** Once per animation frame. */
  frame(nowMs: number, facts: { dpr: number; resolution: number; width: number; height: number }): void;
}
```
- DOM, not a Pixi `Text`: it stays sharp at the capped resolution and a script can read it. Style (inline): `position: fixed; left: 4px; top: 22px; font: 12px monospace; color: #fff; background: rgba(0, 0, 0, 0.5); padding: 0 2px; pointer-events: none; white-space: pre`.
- Periods of ≥ 1000 ms: count frames and the largest frame delta; when a period ends, set `textContent` to `` `fps ${Math.round(frames * 1000 / elapsed)} · worst ${Math.round(worstMs)} ms · dpr ${dpr} → ${resolution} · ${width}×${height}` `` (resolution printed with at most 4 decimals, no trailing zeros, e.g. `1.3125`, `1.5`, `2`), then start a new period. Empty until the first period ends.

### Emulation profiles (`scripts/perf-profiles.mjs`, new; the one source of the recipe)
```js
export const PHONE = { name: "phone", viewport: { width: 390, height: 844 }, deviceScaleFactor: 3, isMobile: true, hasTouch: true, cpuThrottle: 4 };
export const DESKTOP = { name: "desktop", viewport: { width: 1280, height: 720 }, deviceScaleFactor: 1, isMobile: false, hasTouch: false, cpuThrottle: 1 };
/** M0's recipe, Chrome/Lighthouse "slow 4G": 1.6 Mbit/s down, 750 kbit/s up, 150 ms RTT (CDP wants bytes/s). */
export const SLOW_4G = { latency: 150, downloadThroughput: 200000, uploadThroughput: 93750 };
/** A fresh context + page for `profile`: HTTP cache disabled, CPU throttled by profile.cpuThrottle, network throttled if `network` is given. Caller closes `context`. */
export async function openPage(browser, profile, network = null); // → { context, page }
```
`openPage` uses a CDP session on the page: `Network.enable`, `Network.setCacheDisabled { cacheDisabled: true }`, `Network.emulateNetworkConditions { offline: false, ...network }` when given, `Emulation.setCPUThrottlingRate { rate: cpuThrottle }`.

### fps script (`scripts/measure-fps.mjs`, new)
`node scripts/measure-fps.mjs <url> <phone|desktop> [runs]` (runs default 3; usage error → exit 2). Per run: `openPage(browser, profile)` (no network throttle), an init script that pushes every `requestAnimationFrame` delta into a window array while a `window.__collect` flag is set, `goto(url)`, wait for the `overgrown:first-frame` mark (timeout 30 s), settle 2000 ms, then **idle**: collect 5000 ms; then **walk**: hold `ShiftLeft` + `KeyD`, collect 5000 ms, release. Per window: `fps = 1000 × count / sum(deltas)`, `p95Ms`, `maxMs` (1 decimal). Prints one JSON object: `{ url, profile, runs, canvas: [w, h], idle: { fps, p95Ms, maxMs }, walk: { fps, p95Ms, maxMs }, errors }`, each metric the median over runs. Exit 1 if any console error or page error, else 0.

### Startup script (`scripts/measure-startup.mjs`, new)
`node scripts/measure-startup.mjs <url> [runs] [shot.png]` (runs default 5). Per run: `openPage(browser, PHONE, SLOW_4G)` (cold: cache disabled, fresh context). Init script: wraps `window.Worker` and, for the worker whose URL contains `sim-worker`, records `workerCreatedMs` (`performance.now()` in the constructor), `firstSnapshotMs` and `firstChunkMs` (first `message` of each type). Playwright `requestfinished` + `await request.sizes()` sums `responseBodySize` into `bytes = { js, atlas, other, total }` (atlas = URLs ending `generated/core.json` or `generated/core.png`; await every pending `sizes()` before closing). Wait for the mark (timeout 60 s), then read `firstFrameMs` (the mark's `startTime`) and `atlasJsonEndMs` (`responseEnd` of the resource entry whose name ends in `generated/core.json`). On the last run, if `shot.png` is given, wait 3000 ms after the mark and take a screenshot. Prints one JSON object: `{ url, profile: "phone+slow4g+cpu4", runs: [ {firstFrameMs, workerCreatedMs, atlasJsonEndMs, firstSnapshotMs, firstChunkMs} … ], median: {…same keys}, min: { firstFrameMs }, max: { firstFrameMs }, bytes, byteFloorMs, screenshot, errors }` with `byteFloorMs = Math.round(bytes.total / SLOW_4G.downloadThroughput * 1000)` (the time the bytes alone take). Times are ms since navigation start, rounded. Exit as above.

Both scripts start with `/* global window, document, performance, requestAnimationFrame */` (functions passed to `addInitScript`/`evaluate` run in the page), import Playwright as `scripts/check-page.mjs` does, and import the profiles from `./perf-profiles.mjs`.
