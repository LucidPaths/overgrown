## Locked design

### DOM overlay, not a Pixi layer (decision)
The controls are DOM elements over the canvas, for four reasons:
1. TEC-020 caps the canvas resolution and the canvas is composited `image-rendering: pixelated`. Pixi-drawn circles would come out blocky and resolution-dependent. CSS circles are crisp at any DPR.
2. The layout is already in CSS client px, which is what DOM positioning uses.
3. Nothing reaches the renderer's sprite or z-order code, and no atlas frames are needed. That keeps "everything is ours" trivially true: no assets at all.
4. Visibility is one `hidden` flag, and a hidden overlay costs zero GPU work on desktop.

### Overlay (`client/src/ui/touch-overlay.ts` + `client/src/ui/touch-overlay.css`, new)
```ts
import "./touch-overlay.css";
export class TouchOverlay {
  /** Builds #touch-ui (hidden) as the last child of `parent`, positioned from currentTouchLayout();
   *  re-lays out on window `resize` (which rotation also fires). */
  constructor(parent: HTMLElement);
  /** Once per render frame. Writes to the DOM only what changed since the last call. */
  update(visible: boolean, stick: StickView | null, buttonsDown: ButtonsDown): void;
}
```
- DOM structure, built once, in this order:
  ```html
  <div id="touch-ui" aria-hidden="true" hidden>
    <div class="tu-stick-base"></div><div class="tu-stick-knob"></div>
    <div class="tu-slot"></div> ×4   (ring order = RING_ANGLES_DEG order)
    <div class="tu-dodge"></div><div class="tu-attack"></div>
  </div>
  ```
- **Root.** `#touch-ui { position: fixed; inset: 0; pointer-events: none; z-index: 1; }`. `pointer-events` is inherited and no child sets it, so every touch and mouse event lands on the canvas, where CMB-002's adapters listen. Visibility is only the `hidden` attribute; the CSS gives `#touch-ui` no `display` rule, so `hidden` wins.
- **Placement.** Every control is `position: absolute; left: 0; top: 0; border-radius: 50%; box-sizing: border-box`, sized `2r × 2r` from its layout `Circle`, and placed with `transform: translate(x − r px, y − r px)`.
  - Attack, dodge and the ring slots are placed on construction and on `resize`.
  - The stick base and knob are placed by `update`.
- **Sizes** (CSS px, from CMB-002's constants): attack 88, dodge 56, ring slots 48, stick base 112 (`2 × STICK_RADIUS_PX`), stick knob 48 (`STICK_KNOB_PX = 48` in this file, tunable).
- **Look.** Semi-transparent white on the world, no labels or icons in M1. Starting values, tunable:
  - `.tu-attack`, `.tu-dodge`: `background: rgba(255,255,255,0.16); border: 2px solid rgba(255,255,255,0.5)`.
  - `.tu-attack.tu-down`, `.tu-dodge.tu-down`: `background: rgba(255,255,255,0.4)`.
  - `.tu-slot` (greyed out until CMB-003): `background: rgba(255,255,255,0.05); border: 2px dashed rgba(255,255,255,0.2)`.
  - `.tu-stick-base`: `background: rgba(0,0,0,0.12); border: 2px solid rgba(255,255,255,0.35)`. `.tu-stick-knob`: `background: rgba(255,255,255,0.35)`.
  - `.tu-idle` (set on the base and knob while no stick is held): `opacity: 0.5`.
  - No transitions or animations.
- **`update(visible, stick, buttonsDown)`:**
  - `root.hidden = !visible`.
  - With `stick === null`: base and knob both centred on `layout.stickRest` with `tu-idle` (the ghost stick). Otherwise: base centred on `(originX, originY)`, knob on `(knobX, knobY)`, `tu-idle` removed. The knob is already clamped by CMB-002.
  - Toggle `tu-down` on attack and dodge from `buttonsDown`.
  - Each write happens only when its value changed. The steady state does no DOM writes.
- **Safe area.** It comes only through `currentTouchLayout()`: CMB-002's probe reads `env(safe-area-inset-*)`, and `viewport-fit=cover` is already in `index.html`. The overlay CSS does not use `env()` itself, so the drawn circles and the hit circles can never disagree.

### Auto-switch (A-39)
- Visible ⇔ `hostInput.active === "touch"`.
  - Initial state: CMB-002 already seeds `active` from `matchMedia("(pointer: coarse)")`.
  - Any touch `pointerdown` makes `touch` active.
  - Mouse/pen pointer events and handled keyboard events (bound keys only) make `keyboard-mouse` active.
- This task adds no listeners for switching. The rule lives in one place (CMB-002's activity flags), and the same flag also picks whose held input is sent. Do NOT add `mousemove`/`mousedown` listeners: every touch tap fires those as compatibility events (CLAUDE.md trap).
- Both input paths stay live while hidden. A touch on a hidden overlay still drives the stick on that very touch.

### Wiring (`client/src/main.ts`)
- After `const touch = new TouchInput(…)`: `const overlay = new TouchOverlay(appRoot);`. `showFatal` replaces `#app`'s content, so a fatal error also removes the overlay.
- Ticker: the `try` now wraps the whole callback body. Its first statement is `overlay.update(hostInput.active === "touch", touch.stick, touch.buttonsDown);`, followed by the existing `if (curr === null) return;` and the rest, unchanged. The overlay then shows before the first snapshot, and an overlay error still reaches `showFatal`.
- There must be no `await` between `app.ticker.add` and the construction of `hostInput`, `touch` and `overlay`, or the first tick reads them in their temporal dead zone. If the base has one (TEC-021 may add it), register the ticker after those constructions instead.

### Page chrome (`client/index.html`)
Add to the existing `html, body, #app` rule: `-webkit-tap-highlight-color: transparent; -webkit-touch-callout: none; -webkit-user-select: none;`. This stops mobile browsers from flashing a highlight or opening a callout or magnifier when a thumb holds the canvas. Nothing else in the file changes.

const URL = "http://localhost:4203/?seed=1";
const errors = [];

function instrument() {
  const Base = window.Worker;
  window.__you = null;
  window.Worker = class extends Base {
    constructor(...args) {
      super(...args);
      this.addEventListener("message", (e) => {
        const s = e.data && e.data.snapshot;
        if (!s) return;
        const i = s.ids.indexOf(s.you);
        if (i >= 0) window.__you = { tick: s.tick, x: s.x[i], y: s.y[i], facing: s.facing[i], action: s.action[i] };
      });
    }
  };
}

async function open(browser, options) {

  const page = await context.newPage();

  await page.goto(URL);
  await page.waitForFunction(() => window.__you !== null, null, { timeout: 5000 });
  await page.waitForTimeout(300);
  return { context, page };
