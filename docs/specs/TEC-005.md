# TEC-005: Client loads pipeline atlases and draws entities from them

GDD: docs/gdd/01-tech.md — "Asset loader for pipeline atlases + JSON metadata."
Milestone: M0   Depends on: ART-001, TEC-003 (merged)
Model: sonnet — it wires a known Pixi API; the contract (atlas JSON = TexturePacker JSON Hash) is already fixed by ART-001.
Branch: tec-005-asset-loader

## Desired result
The client loads `generated/core.json` (and its PNG) with Pixi's built-in spritesheet support before starting the sim. Entities are drawn with atlas frames chosen by their `Kind` instead of white squares, over a tiled checker backdrop. A missing atlas or frame stops the game with a readable message, never blank sprites.

## Locked design
- `client/src/assets.ts`: `export async function loadCoreAtlas(): Promise<Spritesheet>`. It uses `Assets.load("generated/core.json")`, a relative URL so it works under the Pages subpath (vite base `./`). If the result isn't a Spritesheet, or loading fails, throw `Error("couldn't load the core atlas (generated/core.json): <cause>. Run npm run build (or python3 tools/art/build.py) to generate it.")`.
- `client/src/render/kind-frames.ts`: `export const KIND_FRAMES: Record<KindValue, string>`, where `KindValue` is the union of `Kind`'s values (derive the type from `Kind`, don't restate it). For now it holds `{ [Kind.DebugMover]: "debug/mover32" }`. Adding a Kind without a frame then fails typecheck. Also `export function requireFrames(sheet, names): void`, which throws naming every missing frame and the atlas.
- `client/src/render/snapshot-view.ts`: the constructor takes the Spritesheet. Sprites use `sheet.textures[KIND_FRAMES[kind]]` with anchor 0.5 at native size (integer scale, nearest). An unknown kind at runtime throws an actionable error instead of drawing magenta.
- `client/src/main.ts`: after Pixi init, `await loadCoreAtlas()` and `requireFrames(sheet, [...Object.values(KIND_FRAMES), "debug/checker16"])`. Add a `TilingSprite` of `debug/checker16` covering the 640×360 mover area, behind the entities. Only then start the worker. Load or frame errors go through the existing `showFatal`.
- Root `package.json`: the `dev` script runs the art pipeline first (`python3 tools/art/build.py && npm -w @overgrown/client run dev`), so `npm run dev` never serves without assets.
