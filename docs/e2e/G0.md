## 4. Walk, sprint, dodge, attack with keyboard, mouse and gamepad: PASS

Driver: `docs/e2e/G0/input_driver.gd`, run as

```
G0_OUT=docs/e2e/G0 timeout 300 xvfb-run -a -s "-screen 0 1280x720x24" godot --path game --audio-driver Dummy \
  --rendering-method forward_plus --script "$PWD/docs/e2e/G0/input_driver.gd" -- --seed 1
```

→ exit 0, **`DONE 43 checks, 0 failed`**, 0 error lines (full log `G0/input_driver.log`). Seed 1, starting at the spawn (−59.5, −59.5). Rules ticks are 60/s. Every measurement starts after the injected events have been dispatched (Godot flushes parsed events once per rendered frame, so the driver waits 3 frames before measuring). The first two driver runs that got past parsing had 8 and then 3 failing checks; all were the driver's own timing or threshold mistakes, fixed in the driver (measuring before a frame had dispatched the event; 60 sprint ticks = 8 m, not 12). None were game failures.

**What was injected.** `InputEventKey` with `physical_keycode` = `keycode` (D, W, A, S, Shift, Space, V), pressed then released. `InputEventMouseButton` (left button at the cursor; wheel up and down), and `InputEventMouseMotion`. `Input.warp_mouse(screen point)` moves the real X cursor. `InputEventJoypadMotion`, device 0 (left stick x/y, right stick x/y, right trigger). `InputEventJoypadButton`, device 0 (LB, X, B, Y).

**Mouse path finding.** A parsed `InputEventMouseMotion` alone doesn't move the aim: `get_viewport().get_mouse_position()` stayed (640, 360), because the root viewport reads the OS cursor. After `Input.warp_mouse(332, 420)` it read (332, 420), and the X motion event alone switched the HUD to `keyboard + mouse`. So mouse aim was tested with the real cursor.

## 9. Failure → new GDD task

**GOD-007** (`docs/gdd/01-tech.md`): `--capture-tick 0` never captures.

- `bash tools/godot/capture.sh x.png forward_plus --seed 1 --capture-tick 0` → `SPAWN …`, then `WATCHDOG TIMEOUT` after 1 min 35 s, exit 2, no PNG (`G0/60-capture-tick-0-hang.log`).
- The same command with `--capture-tick 1` → exit 0 in 12 s.
- Cause: in `game/scenes/main.gd` `_run_script`, `_frozen = capture_tick == 0` is set before world ready, and `_physics_process` returns early while `_frozen`. So `sim.step()` and `store.step()` never run, no chunk streams, and world ready never comes. The flag's help says "freeze the rules after N ticks counted from world ready", and the parser accepts 0.

## 10. Lucid's playtest (the gate for feel and fps)

Download **`overgrown-windows.exe`** from <https://github.com/LucidPaths/overgrown/releases/tag/latest> (built from `6112b6a`; the HUD's first line reads `v0.1.0 (6112b6a2)`). It's unsigned. The first time, Windows SmartScreen says "unknown publisher": click **More info**, then **Run anyway**.

Try:
1. **Start:** a short wait (the spawn search takes about 2–3 s at start), then the wanderer stands on grass. Note how long until the world appears and whether the window looks frozen meanwhile.
2. **Keyboard + mouse:** WASD or the arrows to walk, **Shift** to sprint, **Space** to dodge (it rolls along your move keys, or toward the cursor when standing still), **left click** to attack toward the cursor. Check that the facing follows the cursor on attacks, and try a double click (the second swing should chain).
3. **Zoom:** the mouse wheel (8–24 m). **Vista:** hold **V** to pull out to the wide view, and release to come back.
4. **Gamepad** (Xbox layout): left stick to walk, **LB** (or the left-stick click) to sprint, **B** to dodge, **X** or **RT** to attack, the **right stick** to aim, and hold **Y** for the vista. The HUD's third line should switch between `input: gamepad` and `input: keyboard + mouse`.
5. **Collision:** walk into a river (shallow water slows you to about 60 %, and deep water stops you) and into a cliff wall (it stops you, and you slide along it).
6. **Feel and fps:** the HUD shows fps. Judge the walk, sprint, dodge and attack timing and the camera follow.

Known feel notes (already known, so no need to report them):
- The wanderer is about 80 px tall at the default zoom, and the dodge tuck reads small.
- A held stick is ignored after a mouse jiggle until the stick moves.
- Curved cliff walls show a staircase, and river banks show sawtooth edges.
- The spawn search takes about 2–3 s at start.
